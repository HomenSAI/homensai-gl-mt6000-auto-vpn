## 2. Как работать экономно (метод)

Этими приёмами план для Rent был сделан примерно за $15–20 вместо сотен.

1. **Не читай большие файлы целиком.** Сначала измерь: `wc -c`, `wc -l`, `ls -la | sort`. Читай только начало (`head -c 2500`), оглавление (`grep -n "^#"`) и нужные места через `grep -n` с обрезкой строк (`cut -c1-200`).
2. **Одна команда — много ответов.** Объединяй проверки в один вызов shell через `;`. Каждый отдельный вызов заново оплачивает весь накопленный контекст.
3. **Обрезай вывод.** Всегда `| head -N`, `| tail -N`, `| cut -c1-200`. Файл с длинными строками без обрезки может съесть десятки тысяч токенов за раз.
4. **Числа получай скриптом, а не глазами.** Подсчёты, сверки «ничего не потеряно», списки файлов — короткий `python3 - <<'EOF'`.
5. **Не запускай субагентов для чтения.** Субагент стартует с нуля и перечитывает правила. Запускай его только для большой механической работы с точным заданием (шаг 6 раздела 5) и на дешёвой модели.
6. **Не запускай длинные тесты ради анализа.** Бери результаты из уже записанных отчётов. Тесты нужны только после своих правок и только те, что относятся к делу.
7. **Сохраняйся часто.** Коммит и push после каждого шага и не реже раза в 15–20 минут: лимит может кончиться в любой момент. Незавершённое коммить с пометкой `WIP:` и перечнем «сделано / осталось».
8. **Вопросы владельцу — только инструментом вопросов с вариантами**, блоком до 4 штук, с рекомендуемым вариантом первым. Не текстом в конце ответа.
9. **Отчёт владельцу короткий:** время, что сделано, что осталось, расход. Без пересказа шагов.
