# Общий план: Lua-ядро, суточный тест сбоев, ветка на C (утверждён владельцем 31.10.2026)

Решение владельца: довести все 8 пунктов Lua-плана, проверить систему сутками под матрицей сбоев (сбой каждые 5 минут, включая имитацию отключения питания), собрать и опубликовать статистику с графиками, затем сделать отдельную ветку на C. Логика на C пишется сразу (отдельный агент), а после суточного теста сверяется с фактами и корректируется.

Правила те же: один шаг → тесты на ПК → проверка на MT3000 → замер в документации → следующий шаг. Lua-линия в ветке `feat/lua-core-20261030` (2.0.0-alphaN), сохранение в Gitea после каждого шага, на GitHub — в отдельной ветке после тестов. Основная машина MT6000 и сеть Windows не затрагиваются. Неудачные результаты сохраняются.

## Матрица сбоев суточного теста (шаг 10–11)

Сбой каждые 5 минут по кругу; между сбоями система должна вернуться в рабочее состояние. Для каждого сбоя записывается: время обнаружения, время переключения трафика, время готовности, возврат на основной канал, процессор и память, потерянные пакеты LAN, код результата.

| Группа | Сбой | Как создаётся | Ожидаемое |
|---|---|---|---|
| Канал | основной туннель выключен | `ifdown` интерфейса основного канала | переход на резерв, возврат после восстановления |
| Канал | основной сервер недоступен | правило firewall на адрес сервера | переход на резерв |
| Канал | потери/задержка на основном | `tc netem`, если модуль есть на MT3000 | переход только при устойчивом ухудшении |
| Канал | короткий провал 5–20 с | кратковременная блокировка | без переключения |
| Канал | DNS через туннель не отвечает | блокировка DNS в туннеле | диагноз и переход по правилам |
| Канал | оба канала недоступны | блокировка обоих | понятный код, без зацикливания, LAN не заблокирован навсегда |
| Канал | резерв недоступен, основной жив | блокировка резерва | без переключения, предупреждение |
| Процесс | kill службы в покое | `kill -9` | перезапуск procd, состояние сохранено |
| Процесс | kill посреди переключения | `kill -9` в APPLYING/WAIT-CLIENT | откат или завершение, защита LAN снята |
| Управление | ручное переключение во время сбоя | кнопка через RPC | отказ с кодом или выполнение по правилам |
| Питание | мгновенная перезагрузка без записи на флеш | `echo b > /proc/sysrq-trigger` (раз в час, в разных фазах) | загрузка, LAN работает, журнал в проверенном состоянии |
| Питание | настоящее выдёргивание вилки | владелец вручную или управляемая розетка | то же |

Имитация питания чаще раза в час не делается, чтобы не изнашивать флеш и не терять интервалы наблюдения.
