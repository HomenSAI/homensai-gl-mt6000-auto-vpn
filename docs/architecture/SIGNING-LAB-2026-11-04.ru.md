Работа VPN, монитора и Auto не затронута, файлы роутера не менялись.

Настоящие ключи здесь не создаются и не читаются. Сначала всё проходится на тестовом наборе. Настоящие ключи владелец делает только после чек-листа в разделе 6.

## 1. Как запустить

Из любой папки, пока ветка не влита:

```
py -3.14 C:\homensai\homensai-gl-mt6000-auto-vpn\private\signing-lab-src\scripts\signing\lab.py
```

После слияния в основную ветку, из папки репозитория:

```
py -3.14 scripts/signing/lab.py
```

Откроется браузер на `http://127.0.0.1:<случайный порт>`. Ссылка одноразовая. Если браузер не открылся, ссылка будет в окне консоли. Остановка: кнопка «Стоп» или Ctrl+C. Без обращений страница сама закрывается через 4 часа.

Прочие варианты:

| Команда | Что делает |
|---|---|
| `lab.py --run-all-drills` | все учения без страницы, с авто-кодами, в отдельной временной папке; код выхода 1, если есть FAIL |
| `lab.py --run-all-drills --only g,h --no-network` | только выбранные; без сети OpenTimestamps даёт SKIP |
| `lab.py --lab D:\другая\папка` | другая папка лаборатории (или `HOMENSAI_SIGNING_DIR`) |
| `lab.py --reset` | стереть папку лаборатории |
| `keytool.py <команда> --lab <папка>`, `agetool.py <команда> --lab <папка>` | любая команда инструментов на лаборатории |
| `reveal-secret.ps1 -Lab <папка>`, `import-secret.ps1 -Lab <папка>`, те же для age | то же из PowerShell |

Папка лаборатории по умолчанию: `C:\homensai\homensai-gl-mt6000-auto-vpn\private\signing-lab\`. Отчёт: `DRILLS.html` в ней, кнопка «Отчёт» на странице.

Исходники ветки лежат в `private\signing-lab-src`, а не в `private\signing-lab`: иначе одна папка была бы и кодом, и лабораторией, и кнопка «Сброс» стёрла бы код. Сейчас лаборатория отказывается работать в папке с `.git` (`LAB-DIR-IS-A-CHECKOUT`).

## 2. Как устроено

| Что | Настоящее | Лаборатория |
|---|---|---|
| Секреты | `private/signing/*.dpapi` | `<лаборатория>/store/*.dpapi`, DPAPI с другой энтропией |
| Открытые ключи, список отзыва, комплект | дерево репозитория | `<лаборатория>/repo/` (свой маленький git с фиктивной историей) |
| Цепочка | `releases/CHAIN.jsonl` | `releases/CHAIN-LAB.jsonl` |
| Key id | 8 случайных байт | начинается с `1ab01ab0` |
| Комментарий `.pub` | `HomenS.AI Auto VPN release key ...` | `TEST LAB KEY, NEVER FOR A RELEASE: ...` |
| Строка секрета | `HSAI-SK1:...` | `HSAI-SK1-LAB:...` |
| Запись в Google Authenticator | `HomenS.AI Auto VPN:release-signing` | `HomenS.AI TEST LAB:signing-drills` |
| age | `scripts/backupcrypt/recipients.txt` | `repo/scripts/backupcrypt/recipients.txt` |

Режим определяется файлом-меткой `HOMENSAI-SIGNING-LAB.json` в корне лаборатории. Логика подписи, цепочки, TOTP, кодов, импорта и age не продублирована: учение вызывает `keytool.main()` и `agetool.main()` с `--lab`, как если бы владелец ввёл команду сам. Подменена только консоль (вопросы и вывод). Поэтому пройденное учение проверяет настоящий путь. Есть и тест обратной стороны: если инструмент перестаёт отказывать, учение даёт FAIL.

**Изоляция в обе стороны:**

| Попытка | Результат |
|---|---|
| Настоящий `Store` на папке лаборатории, также через `HOMENSAI_SIGNING_STORE` | `STORE-LAB-DIR-REFUSED` |
| Лаборатория на `private/signing`, её родителях или вложенных папках | `LAB-DIR-REAL-STORE` |
| Лаборатория в рабочей копии git / в домашней папке / в чужой непустой папке | `LAB-DIR-IS-A-CHECKOUT` / `LAB-DIR-UNSAFE` / `LAB-DIR-NOT-EMPTY` |
| Тестовый секрет в настоящем `sign-release` | `SIGN-LAB-KEY-REFUSED` |
| Настоящий секрет в лабораторном `sign-release` | `SIGN-REAL-KEY-IN-LAB` |
| Тестовый ключ в настоящем списке доверия | `KEYS-LAB-KEY-REFUSED` |
| Настоящий ключ в лабораторном списке | `KEYS-REAL-KEY-IN-LAB` |
| Тестовая строка в настоящем `import` | `IMPORT-LAB-KEY-REFUSED`, ничего не сохранено |
| Настоящая строка в лабораторном `import` | `IMPORT-REAL-KEY-IN-LAB`, ничего не сохранено |
| Блоб DPAPI, скопированный между хранилищами | не расшифровывается (разная энтропия) |
| Тестовый ключ в записи релиза (`keys/`, цепочка или `.sig`) в `publish-reviewed.py` | `PUBLICATION-LAB-KEY` |
| `publish-reviewed.py` при заданном `HOMENSAI_SIGNING_DIR` | `PUBLICATION-LAB-ENV` |
| Смешение настоящего дерева и лабораторного хранилища | `LAB-MODE-MISMATCH` |
| Авто-ответы (`LabConsole`) с настоящим хранилищем | `LAB-CONSOLE-REAL-STORE` |

Архив секретов (`secrets_archive.py`) папки `signing-lab` и `signing-lab-tools` не берёт. `private/` не попадает в git.

**Сброс** стирает только папку лаборатории. Перед удалением заново проверяются путь и метка.

## 3. Страница

- Только `127.0.0.1`, порт выбирает система. Параметра адреса не существует.
- Токен из ссылки работает один раз и 5 минут, затем становится cookie (`HttpOnly`, `SameSite=Strict`), адрес очищается.
- POST требует CSRF-токен страницы, свой `Origin`, `application/json`. Каждый запрос проверяет `Host` (защита от DNS rebinding).
- CSP: только встроенные скрипт и стили с nonce, внешних файлов нет. Ответы не кешируются.
- Журнала запросов нет. Ответы владельца идут только в теле POST.
- Секрет передаётся странице один раз и сразу заменяется в памяти сервера пометкой. После обновления страницы он не появится.
- Вывод инструментов проходит маскировку до записи в журнал, `drills.json` и `DRILLS.html`.
- В памяти процесса на время работы лежат показанные тестовые строки и коды: они нужны режиму «Авто». На диск не попадают и исчезают при остановке.
- Лимит кодов прежний: 5 неверных подряд, блокировка 10 минут. Его держит `totp.py`, потому что все коды идут через настоящие команды.

**Два режима сценария.** «С телефоном» спрашивает настоящие 6 цифр и коды с листа. «Авто» считает код из тестового семени. Учения i, j, k, l и часть h работают на временной копии лаборатории: там коды всегда автоматические, а секреты копии на страницу не выводятся. Поэтому порядок учений не важен, и они не портят ваш тестовый набор. Отозванный на копии ключ не появится в карточке «Состояние»: итог виден в журнале учения и в отчёте.

«Запустить все учения» и `--run-all-drills` работают в отдельной временной папке и на виртуальных часах. Иначе каждый код ждал бы новый 30-секундный шаг. Виртуальные часы и авто-ответы доступны только лабораторному хранилищу. В настоящем пути их нет.

## 5. Что найдено и что НЕ покрыто

**Найдено учением e:** `import` не записывал ключ в `keys.json`, и на новом ПК индекс оставался пустым. Подпись от этого не зависела. Исправлено в `keytool.py`.

**Подтверждённый предел (учение j).** Роутер, который ещё не получил релиз с отзывом, примет следующий релиз, подписанный украденным ключом. Поэтому отзыв нужно выпускать сразу. Это не ошибка, а граница схемы.

**Не покрыто:**

- Настоящий роутер. Симулятор проверяет логику скриптов, а не `opkg`, flash-память и настоящий пакет.
- Настоящая Windows-переустановка: «новый ПК» изображён очисткой хранилища на той же учётной записи. Перенос DPAPI на другой компьютер не проверялся, но секреты туда и не переносятся, только строка.
- Сканирование QR камерой в автопрогоне. На странице QR настоящий, импорт идёт вставкой текста скана. Цикл «QR → декодер → импорт» подтверждён отдельно (`qa/evidence/signing-2026-11-03/qr-roundtrip.json`).
- Подтверждение OpenTimestamps в Bitcoin: учение ждёт только `pending`, подтверждение приходит через часы.
- `homensai-vpn-trust-key` на настоящем роутере не отличает тестовый ключ: администратор может вручную довериться `.pub` с меткой TEST. Защита здесь только в комментарии файла и префиксе id. Менять файл роутера в этой задаче запрещено (это смена версии пакета).
- Плановая ротация после потери main: новая пара через reserve описана в руководстве, отдельной команды нет, учения её не проходят.
- Защита от вредоносной программы в сессии владельца: как и в основном руководстве, TOTP и DPAPI в одной сессии Windows.
- Лаборатория не проверяет настоящие ключи: она доказывает инструменты и порядок действий.

**Доказательства** (`qa/evidence/signing-lab-2026-11-04/`):

- Все 14 учений (a–n; учение o добавлено позже, см. раздел 12 руководства по подписи): PASS на Windows, Python 3.14, настоящий DPAPI, alpine с настоящим usign, настоящие календари OpenTimestamps (`drills-run.json`).
- Десять учений пройдены «с телефоном» через HTTP на настоящих часах: роль телефона и листа играл скрипт.
- Страница нажата в настоящем Edge: без ошибок CSP и консоли, QR, коды, печать, смена языка, диалог сброса.
- Набор qa и tools на Linux: Python 3.11 полностью; Python 3.9 без учений и страницы, потому что в этом образе нет git. Тесты лаборатории на Windows (Python 3.14 и 3.15). Мутации в контейнере: 49 из 49 убиты (`mutations.json`, драйвер `mutation_driver.py`).

## English summary

A rehearsal bench for the signing tools. `scripts/signing/lab.py` serves one self-contained page on 127.0.0.1 with a random port and a one-time link, and `--run-all-drills` runs every scenario headless. Each drill calls the real `keytool.main()` / `agetool.main()` with `--lab`, so only the console is replaced. Test keys carry the key id prefix `1ab01ab0`, the secret tag `HSAI-SK1-LAB`, their own DPAPI entropy, chain file and trust list. The real tools, `sign-release` and `publish-reviewed.py` refuse them, and a lab refuses real keys and the real store. Router steps run the real install script and trust tool in an offline alpine container with the real OpenWrt usign, never on a device. See sections 5 and 6 for the limits and the move to real keys.
