## 2. Находки

- **Н1 (важная) [Ф].** Сбой загрузки модуля Lua Auto не доходит до запасного Python. Прогон `auto.lua daemon` с
  каждым из 56 модулей, обрезанным наполовину: **22** модуля на пути загрузки (`attest auto auto_control backend canon
  control deps diagnosis durable identity journal kernel manual net pair platform py recovery rollback runner sys
  transaction`) → выход 1 сразу, `lua-auto-crashes.json` не создаётся, `LUA-AUTO-FALLBACK` невозможен; остальные 34
  → процесс работает (ошибка возможна позже в проходе — тогда счётчик сработает). Под procd (`respawn 3600 5 0`,
  retry 0 = бесконечно) это вечный перезапуск каждые 5 с с ошибкой в `logread`. Трафик при этом не трогается
  (guard — таблица nft в ядре, смерть процесса её не снимает [К]), но **восстановление журнала после загрузки не
  выполняется** — незавершённое переключение остаётся неоткаченным до ремонта. Тест: `AutoDaemonLoadErrorTest`
  (ожидаемый отказ). Исправление (предложение): в `auto.lua`/init обернуть загрузку модулей в `pcall` и считать
  такие падения тем же счётчиком, либо init выбирает Python, если проверка целостности не прошла.
- **Н2 [Ф].** Пустой (0 байт) или обрезанный до комментариев модуль Lua «загружается» как `true`. Пример: половина
  `terms.lua` → `TERMS_VERSION=true` → Auto отказывает `TERMS-NOT-ACCEPTED` (безопасно, но код вводит в заблуждение:
  владелец будет «принимать условия» заново, а виноват файл). Так же `version.lua`.
- **Н3 [Ф].** Один изменённый байт может дать **корректный** Lua с другим смыслом (`'2'`→`'3'` в `terms.lua`). Ни
  один существующий слой это не видит; отличить «повреждено» от «так задумано» может только контрольная сумма.
- **Н4 [К].** Монитор: init проверяет только наличие `monitor.lua`, не `-x /usr/bin/lua` и не целостность; Python-монитор
  выбирается лишь при `lua_monitor=0`. Битый модуль монитора → вечный перезапуск; страница отвечает через `agent.py`
  (данные без живых измерений).
- **Н5 [К].** Права на чтение для root не важны (служба — root); важен только бит исполнения у init, rpcd-плагина и
  emergency. Без него: служба не стартует при загрузке / объект страницы пропадает.

нет и не будет — это вне модели угроз.

## 5. Где держать копию и сколько она стоит (вопрос 2)

- Пакет 1 447 264 байт (`data.tar.gz`; с манифестом 1 458 581), распакован 4,4 МБ [Ф]. При ~110 МБ свободных на
  overlay одна копия — ~1,3 %; две (текущая + предыдущая на время обновления) — ~2,7 %.
- **Место:** `/etc/homensai-vpn/pristine/<имя>_<версия>.ipk` + `.sha256`, каталог `0700`. Тот же UBIFS, что и
  программа: физической независимости нет (отдельного раздела под это нет), но от повреждения отдельных файлов —
  достаточно; UBIFS сам проверяет CRC узлов. `/etc` попадает в резервную копию прошивки [П: `sysupgrade -l`] —
  копия переживёт и перепрошивку с сохранением настроек.
- **Защита копии:** sha256 рядом; проверка перед каждым использованием; запись — `durable.write`-способом
  (временный файл, fsync, rename); при обновлении новая копия кладётся **до** `opkg install`, старая удаляется
  только после успешного postinst. Копия повреждена → `INTEGRITY-SOURCE-DAMAGED`, восстановления нет, только код.
- Кладёт копию набор установки (`02-install.sh`) или postinst (если пакет знает свой путь) — решение координатора.

## 6. Служба самопроверки (вопрос 3)

1. **Когда:** (а) в `start_service` до `procd_open_instance` (≈ 4,4 МБ sha256 — доли секунды [П: замерить]);
   (б) отдельный init `homensai-vpn-integrity` START=98 — проверяет и при порче чинит основной init; (в) раз в сутки
   таймером hv-core/монитора (только проверка, без восстановления на ходу).
2. **При несовпадении:** не трогать guard и правила (таблица nft остаётся); не запускать Auto-экземпляр (Auto стоит
   безопасно, `native_enabled` не меняется — это решение владельца); `restore` заменяет **только** испорченные
   файлы (временный файл + `chmod` + `mv`), conffile и `/etc/homensai-vpn/*` не трогает; повторная проверка;
   при успехе — обычный старт (recover журнала выполнит Auto); код в `logread` и
   `/var/run/homensai-vpn/integrity.json` для страницы.
3. **Без петли:** одно восстановление на загрузку (маркер в RAM), не более 3 за 24 ч (журнал в `/etc`, будущие
   отметки тоже считаются); неудача → `INTEGRITY-RESTORE-FAILED`, служба остаётся в безопасном стопе до владельца.
4. **Никогда автоматически:** `/etc/config/homensai_vpn` (включая `terms_version`), сертификаты, журнал, история,
   токены; флаг Auto; nft/маршруты. Скачивание из сети — только по кнопке владельца.
5. **Порядок отката:** C → чистый Lua (есть) → Python (есть для ошибок прохода; Н1 — добавить для ошибок загрузки)
   → безопасный стоп с сохранённым guard и кодом → `homensai-vpn-emergency` (добавить `verify` и `restore`).

## 9. Реализация (TODO 15, ветка `lua/agent-integrity2-20261101`)

**Источник байтов — выбрано: снимок из postinst, а не `.ipk`.** opkg 21.02 не передаёт сценариям пакета путь к
`.ipk` (скачанный пакет лежит во временном каталоге и удаляется; `$PKG` нет) [К; П — проверить `env` в postinst].
Поэтому postinst вызывает `homensai-vpn-integrity snapshot`: только что распакованные opkg файлы сверяются с
манифестом **из того же пакета** (каждый файл, sha256 + режим); если всё совпало — `tar.gz` этих файлов (без conffile)
+ манифест → `/etc/homensai-vpn/pristine/payload.tar.gz` (+ `.sha256`, каталог 0700; временный файл → `sync` → `mv`).
По содержимому это ровно полезная нагрузка пакета, и способ работает при любой установке (набор, LuCI, opkg по URL).
Отказ (`INTEGRITY-SNAPSHOT-REFUSED`, `-NO-SPACE` при < 8 МБ свободных) установку не прерывает.
