# Lua-ядро: alpha1 (мгновенное ручное переключение)

Дата: 30.10.2026 · Ветка: `feat/lua-core-20261030` · Линия пакета: `2.0.0-lua-alphaN` · План целиком: `LUA-PROJECT-2026-10-30.ru.md` (документ владельца, здесь не дублируется).

Пометки: **[Ф]** — факт (замер на MT3000, код или тест), **[О]** — оценка, **[П]** — проверить на роутере.

Статус: код и тесты alpha1 готовы в рабочем дереве, **не закоммичены**, на роутере не запускались. Python-линия не изменена: ни один Python-модуль не вызывает Lua-ядро, пакет собирается как раньше (новые файлы лежат в нём инертно).

## 1. Что делает alpha1 (проект §6)

Python-супервизор оставляет за собой всё, что было до записи: облегчённую проверку нажатия, диагностику, аттестацию ядра до записи, `pair_policy.transition`, аренду, сборку журнала APPLYING. Вместо записывающей части `native_switch.instant_manual` (reorder → apply → проверка → журнал) он вызывает один процесс:

```
lua /usr/lib/homensai-vpn/lua/instant_switch.lua <primary|reserve> [/var/run/homensai-vpn/instant-request.json]
```

Запрос пишет Python (ОЗУ, 0600):

```json
{"direction":"reserve","control_revision":"<32 hex>",
 "journal":{... журнал APPLYING ровно как в instant_manual ...},
 "names":{"<идентичность секции>":"<имя UCI-секции>", ...},
 "tunnel_order":["<tunnel_id первого>","<tunnel_id второго>"]}
```

Шаги Lua (каждая запись — под `control_lock` с проверкой ревизии управления, как `forward_dispatch`):

1. Проверка запроса и `journal.validate`; текущий журнал должен быть завершённым (`light_gate`).
2. Журнал APPLYING.
3. `uci reorder` + один `commit` в процессе через libuci; выравнивание `gl_process_vpn` по первому правилу (порт `process_policy.synchronization_script`, тот же CAS двух полей); проверка по содержимому (порядок tunnel_id), а не по именам анонимных секций.
4. Один `iptables-save` → план (`fast_policy`); `iptables-restore --noflush` через pipe; ещё один `iptables-save` → проверка «менять нечего» + подмножество `kernel_policy.attest` (ROUTE_POLICY = restore-mark, DNS, переход A, переход B; цепочки туннелей = метка + DROP, метки разные); `conntrack -D` старой метки.
5. Журнал HELD-ON-RESERVE (`reason`, `confirmed`, `reserve_healthy`, `instant_seconds`, `phase_evidence`).

Результат — одна строка JSON на stdout; код выхода 0 (готово) или 2 (отказ с кодом). Отказ до первой записи → журнал ROLLED-BACK / FAILED-BEFORE-APPLY (как Python). Отказ после записи → журнал остаётся APPLYING с `failure_code`, в ответе `rollback_required:true`, откат делает Python (`rollback_counted`, как после своей ошибки). Неподдерживаемая раскладка цепочек → `fallback:"vendor-rebuild"`, решение за Python.

Остаётся в Python в alpha1: всё до записи, откат, guard (`guard_exists/guard`), публикация события и истории, сохранение `manual_hold`. Аттестация после записи в Python (`attest_policy`) может остаться как вторая проверка до замера; Lua-подмножество её не заменяет целиком (нет `ip rule`, PREROUTING, VPN_PREROUTING_HOOK).

Режим `--dry-run` только читает (uci, `iptables-save`, журнал) и печатает тайминги, память, выбранную реализацию sha256 и хэш плана. Он не берёт блокировку и ничего не пишет, кроме временного файла `sha256sum` в `/var/run/homensai-vpn` (ОЗУ, удаляется сразу).

## 4. Координация с Python

- **Блокировка.** Тот же файл `/var/run/homensai-vpn/auto-control.lock`, тот же `flock(2)`. Повторный вход в замок из того же процесса запрещён кодом (`CONTROL-LOCK-REENTRY`), как и в Python он привёл бы к взаимоблокировке. Отличие: Python запускает команду под замком и ждёт её уже без замка; Lua держит замок, пока идёт `iptables-restore` (8–33 мс [Ф]). `rtp2.sh` Lua не запускает никогда.
- **Один владелец журнала.** В alpha1 журнал пишет тот процесс, который ведёт транзакцию: Python вызывает Lua синхронно и не пишет журнал, пока Lua работает. Восстановление после перезапуска остаётся Python (`serve()` читает тот же журнал).
- **Вложенные записи журнала**, которые Lua пока не проверяет полностью (`vendor_profiles`, `pair_transition`, `restore_order_step/proof_source/order_origin`): Lua их не создаёт и не меняет; запись разрешена, только если они байт-в-байт равны записям в журнале, который проверил Python (`JOURNAL-DELEGATED-UNVERIFIED` иначе).
- **Часы.** `started/deadline` (стена) приходят от Python; Lua добавляет `confirmed`/`finished`/`phase_evidence.time` из `nixio.gettimeofday` (без nixio — целые секунды [П]). Монотонное время Lua (`/proc/uptime`) в журнал в alpha1 не пишется.

## 6. Уязвимости и исправления

Проверка прототипа против защит Python-версии. Найдено в первой версии прототипа и исправлено:

| # | Находка | Риск | Исправление |
|---|---|---|---|
| V1 | Командные строки собирались из данных (`'iptables-restore' '--noflush' <путь>`, `conntrack -D -m <метка>`, `flock` с путём), пусть и в кавычках | внедрение в shell при ошибке экранирования; нарушение правила «только постоянные команды» | Все команды — константы (`runner.COMMANDS`, `iptables-restore --noflush`, `conntrack -D -m "$(cat <наш файл>)/0xf000"`, `uci batch <наш файл>`, `sha256sum >наш файл`). Данные идут через pipe или через файл, только что записанный нами. Известное отличие, оставленное сознательно: при отсутствии `timeout` в busybox команды не ограничены по времени [П]; блокировка ждёт без срока, как в Python.

## 7. Оптимизации

- `iptables-save` разбирается один раз на чтение: `kernel.snapshot` (декодирование + разбиение) обслуживает план, старую метку, проверку и `parse_mangle`. В Python тот же текст разбивается 3–4 раза.
- Payload и все списки собираются через `table.concat`, без склейки в цикле.
- UCI: одна сессия libuci и один `commit` вместо процесса на каждый ход.
- Порядок правил после записи читается из libuci, а не процессом `uci show`.
- Одна реализация sha256; при `nixio.crypto` — без процессов.

## 9. Первый замер на роутере (только чтение)

1. Скопировать `router/files/usr/lib/homensai-vpn/lua/` в `/tmp/hvlua/` (не устанавливать пакет).
2. `cd /tmp/hvlua && for i in 1 2 3 4 5; do time lua instant_switch.lua --dry-run; done` — при работающем Auto безопасно: замок не берётся, записей нет (кроме временного файла `sha256sum` в ОЗУ). Ожидается `"changed":false`, `"attest":"verified"`, фаза журнала, `sha256_backend`, `memory.VmRSS`, тайминги `uci_read_ms`, `iptables_save_ms`, `plan_ms`, `attest_ms`, `journal_read_ms`.
3. Сверка с Python на тех же данных: `python3 -c "import sys,hashlib,subprocess;sys.path.insert(0,'/usr/lib/homensai-vpn');import fast_policy as f;u=subprocess.check_output(['uci','show','route_policy']).decode('utf8','replace');m=subprocess.check_output(['iptables-save','-t','mangle']).decode('utf8','replace');o,t,k=f.uci_rules(u);p,a,c=f.plan(m,o,t,k);print(c,hashlib.sha256(p.encode()).hexdigest())"` — хэш должен совпасть с `payload_sha256`. Совпадение `journal` (не код `JOURNAL-INTEGRITY-FAILED`) подтверждает канонический JSON и sha256 на настоящем журнале.
4. Факты среды: `lua -e "print(pcall(require,'nixio'),pcall(require,'nixio.crypto'),pcall(require,'uci'))"`; `command -v flock timeout sha256sum conntrack`; `sh -c '[ /proc/self/fd/0 -ef /proc/self/fd/0 ] && echo ef-ok'`; монотонные часы: `cat /proc/uptime; python3 -c "import time;print(time.monotonic())"`.

Только после этого — запись в окне экспериментов: Python вызывает `instant_switch.lua` вместо записывающей части `instant_manual` за флагом (это изменение Python-кода ещё не сделано), 3+3 ручных переключения, сверка журнала Python-чтением (проект §6).

3. Новые коды (`JOURNAL-DELEGATED-UNVERIFIED`, `CONTROL-LOCK-UNAVAILABLE`, `CONTROL-LOCK-REENTRY`, `COMMAND-FAILED`) — в таблицу ошибок страницы.
4. Порт полного `kernel_policy.attest` (`ip rule`, PREROUTING) и проверок `pair_policy.metadata`/`profile_identity` — для alpha2, когда Lua возьмёт всю транзакцию.

## 11. Возврат к Python-линии

Пока Lua только вызывается Python-кодом, отключение — это флаг или удаление вызова; файлы `lua/` инертны. После выхода отдельного пакета (`homensai-auto-vpn-lua`, `Conflicts: homensai-auto-vpn`, проект §6) — `opkg install` Python-пакета; журнал, ревизия управления и состояние читаются им без изменений (проверено тестами для журнала).
