# Подбор лучшего сервера внутри канала — разбор и замысел (2.1.0), 02.11.2026

Решение владельца 02.11.2026: делать отдельной версией после 2.0.0. При сбое канала трафик сразу идёт на другой канал, как сейчас. Пока он там, программа проверяет серверы упавшего канала, выбирает лучший по пингу и ставит его в этот канал. Возврат идёт уже на этот проверенный сервер. И так по кругу.

## Что уже умеет прошивка GL (прочитано на MT3000 02.11.2026, без изменений)

- У каждого туннеля GL есть **список серверов**: `/etc/vpn_profiles.d/profile<tunnel_id>`, путь записан в `route_policy.@rule[i].profiles`.
  - Канал WireGuard (туннель 5841, NordVPN, группа 10004): `10004_2002` (Berlin), `10004_2000`.
  - Канал OpenVPN (туннель 4192, NordVPN, группа 40354): `40354_2020` (Kyiv), `40354_2016`.
  - Всего в роутере есть 10 серверов WireGuard и 20 серверов OpenVPN этого провайдера. В списки туннелей входят по 2.
- **Свой перебор серверов прошивки:** `/usr/bin/tunnel-switch.sh <tunnel_id>`.
  - Его запускают `vpn-failover-watcher.sh` (если канал не подключился за 30 с) и `vpn-failover-trigger.sh` (при падении интерфейса).
  - Он ждёт 8 с. Если канал не ожил, берёт **следующий** сервер списка по кругу, без учёта пинга.
  - Смена сервера: `route_policy.<rule>.peer_id` или `client_id` (+`group_id`), `network.<iface>.config`, затем `ifdown`/`ifup` интерфейса. Ждёт подтверждённого подключения, потом полная перестройка правил `rtp2.sh`.
  - Это и есть тот перебор серверов, который видит владелец.
- **Внутри одного сервера** OpenVPN сам перебирает 4 адреса: один IP на портах 1231–1234. Адрес WireGuard записан именем (`berlin.de.wg.nordhold.net`), и при переподключении имя может указать на другую машину.

## Что добавим (2.1.0)

1. **Пинг серверов.**
   - Для серверов из списка канала меряем пинг с роутера до адреса сервера через провайдера (WAN), без подъёма туннеля.
   - Этот трафик идёт от самого роутера, а не от устройств сети, поэтому защита от утечек его не касается.
   - Для OpenVPN — время TCP-соединения с портом сервера (ICMP у части серверов закрыт). Для WireGuard — ICMP до адреса, в который разрешается имя сервера.
   - Мерим редко: раз в 10 минут и сразу после сбоя канала.
2. **Порядок списка для прошивки.** Сразу за текущим сервером ставим лучший по пингу. Тогда и собственный перебор прошивки при обрыве берёт лучший сервер, а не просто следующий. Это не требует никаких переключений.
3. **Смена сервера у упавшего канала** (то, что предложил владелец).
   - Условия: канал упал, трафик уже на другом канале, Auto включён, выключатель «Подбирать лучший сервер» включён.
   - Ставим лучший живой сервер тем же способом, что и прошивка: тот же порядок записей и `ifdown`/`ifup` только этого интерфейса. Ждём подключения. Перестройку правил `rtp2.sh` прошивка делает сама, программа уже умеет её пережидать.
   - Проверяем канал через туннель: DNS и HTTPS, как обычную проверку канала. Не прошёл — берём следующий по пингу.
   - Возврат на основной канал — по обычным правилам: уже на новый сервер.
4. **Ограничения.**
   - Канал, по которому идёт трафик, не трогаем никогда.
   - Меняем, только если новый сервер лучше на 20 % и больше или старый не работает.
   - Не больше 4 смен сервера в час на канал.
   - Собственный перебор прошивки не выключаем. Если он уже идёт (блокировка `/var/run/tunnel-switch-tid-<id>.lock`), ждём его.
5. **Интерфейс.**
   - У каждого канала видно текущий сервер.
   - Список серверов с пингом, лучший отмечен.
   - В журнал пишется каждая смена: «сервер канала OpenVPN сменён: Kyiv → Berlin, пинг 48 → 21 мс».
   - Выключатель «Подбирать лучший сервер» (по умолчанию выключен до проверки на роутере) и выбор, из каких серверов подбирать.
6. **Новые коды:** `SERVER-PICKED`, `SERVER-PICK-FAILED`, `SERVER-PICK-WAITING-VENDOR`, `SERVER-PICK-LIMIT`.

## Что проверить на роутере перед кодом

- Поведение `ifdown`/`ifup` одного интерфейса, пока трафик идёт через другой: нет ли простоя у работающего канала во время `rtp2.sh` (замер клиентом сети).
- Как быстро после смены сервера свежие правила проходят проверку (`KERNEL-POLICY-UNVERIFIED`).
- Не мешает ли смена сервера привязке пары: программа следует номеру туннеля (`plan_target_tunnel`), это уже поддержано с alpha27.
