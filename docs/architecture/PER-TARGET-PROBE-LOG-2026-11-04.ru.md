# Журнал проб по целям: что отвечала каждая цель в каждой пробе (`probe_target_log`)

Дата: 04.11.2026. Ветка `feat/per-target-probes-20261104` от `7a857af6` (интеграция 2.1.0-alpha9). Без работы с роутером, без смены версии.
Зачем: исследование корреляции датчиков (`private/math/sensor-correlation/REPORT.ru.html`) не смогло измерить корреляцию между
целями проб. Агент считает результат каждой цели в каждой пробе (три HTTPS-цели 1.1.1.1 / 8.8.8.8 / 9.9.9.9 через
`checks[цель]`, UDP DNS, у Lua-монитора ещё и ICMP-пульс по целям), но нигде его не записывал: в журналах soak есть только
вердикт канала. Теперь записывается.

## 1. Что это и чего это не делает

- Журнал **ничего не измеряет**. Числа берутся из той же пробы, которая вынесла вердикт (одно чтение — один источник): результат и
  время каждой HTTPS-цели из `probe_checks`, `dns_ok`, код канала и счётчики эхо пульса. Новых пакетов нет.
- Журнал **не влияет на решения**: Auto, диагностика и страница его не читают. Любая его ошибка (диск ОЗУ полон, файл подменён
  ссылкой) пишется в системный журнал один раз и не прерывает пробу.
- Журнал **не пишется на flash**: только в tmpfs (`/var/run/homensai-vpn`). После перезагрузки роутера он пуст.
- Единственный писатель — монитор (один процесс, один поток). RPC и набор soak только читают.

## 2. Включение

Опция `probe_target_log` в `config main` (`/etc/config/homensai_vpn`), читается `inventory.lua` для обоих рантаймов:
по умолчанию **включено**; выключает только явный `'0'`:

```
uci set homensai_vpn.main.probe_target_log='0' && uci commit homensai_vpn
```

Значение по умолчанию «1» выбрано потому, что стоимость ничтожна (раздел 6). Страница настройки опции не имеет, как и у `heartbeat_quorum`.

## 3. Файлы и размер

Кольцо из двух файлов в `/var/run/homensai-vpn/`: `probe-targets.log` (текущий) и `probe-targets.log.1` (предыдущий).
Строки только добавляются; когда текущий файл дошёл бы до 128 КиБ, он переименовывается в `.1` (старый `.1` исчезает) и
начинается новый. Всего **не больше 256 КиБ** (2 × 128 КиБ); права 0600; ссылки и не-файлы отклоняются (`O_NOFOLLOW`, проверка типа).
Строка около 80–110 байт, поэтому в кольце помещается порядка 2400–3200 строк: при двух каналах и пробе раз в 10 с — примерно 3,3–4,4 часа;
набор soak забирает новые строки каждый цикл (раздел 5), потери нет. Недописанная последняя строка (обрыв питания, чтение в момент записи)
читателем отбрасывается.

## 4. Формат строки

Одна строка на **канал Auto** (источник и цель пары) на **пробу**. Каналы вне пары не пишутся; без пары не пишется ничего. Строка — JSON-массив
целых чисел (и идентификатор профиля), одинаковый байт в байт у Lua и Python (общие случаи `router/tests/probe_target_log_cases.json`):

```
[seq, t, "id", verdict, flags, [c1,l1, c2,l2, c3,l3], dns, [s1,m1, s2,m2, s3,m3, so,mo]]
```

| Поле | Смысл |
|---|---|
| `seq` | 1, 2, 3 … продолжается после перезапуска монитора (читается из кольца). Если число меньше курсора читателя — роутер перезагружался, кольцо пустое: читать с 0 |
| `t` | время пробы, целые секунды с эпохи |
| `id` | профиль, например `wireguard:peer_7` |
| `verdict` | 0 OK, 1 DNS-001, 2 VPN-003, 3 VPN-001, 4 VPN-MTU, 5 ROUTE-001, 6 CHECK-001, 7 SYSTEM-001, 8 VENDOR-IDENTITY-CHANGED, 9 иной код |
| `flags` | бит 0 — плотная проба подтверждения (`dense`) |
| `c`, `l` | код результата и задержка в мс для `one.one.one.one` (1.1.1.1, `/cdn-cgi/trace`), `dns.google` (8.8.8.8, DNS-JSON), `dns.quad9.net` (9.9.9.9, DNS wire) в этом порядке |
| `dns` | UDP DNS-проверка: 0 ответ, 1 нет, 9 не измерялась (своей задержки у неё нет) |
| `s`, `m` | эхо ICMP-пульса (отправлено / без ответа) с прошлой строки этого канала, по целям 1.1.1.1, 8.8.8.8, 9.9.9.9 и «прочие цели пула» (при `heartbeat_quorum`); `[]`, если эхо не было |

Код результата цели `c`: 0 ok, 1 timeout, 2 tls-error, 3 invalid-response, 4 transport-error, 5 http-error, 6 http-unsupported,
7 unknown, 9 цель в этой пробе не измерялась; **+10**, если ответ не подлинный (`probe_trust`: чужой сертификат, редирект портала,
повторённая страница). Задержка `l` — целые мс (округление вверх с .5, 0…600000), −1 — нет значения. У отказа задержка тоже есть
(время до таймаута или до ошибки).

Пример (источник здоров, у резерва два из трёх таймаута, пульс 10 эхо, у 8.8.8.8 одно без ответа):

```
[41,1762243200,"wireguard:peer_7",0,0,[0,144,0,61,0,88],0,[5,0,5,1,0,0,0,0]]
[42,1762243200,"wireguard:peer_8",2,0,[0,143,1,3001,1,3000],0,[5,0,5,0,0,0,0,0]]
```

Ограничения: у Python-монитора нет пульса (его никогда не было в Python-ветке), поле `[]`; у Lua без `lua_fast_detect` — тоже `[]`;
у DNS нет задержки (проба возвращает только да/нет, менять её ради журнала не стали).

## 5. Чтение: RPC `probe_targets` и набор soak

Только чтение: ubus-метод объекта `homensai-vpn` (в ACL — раздел `read`), аргументы `{"after": N, "limit": M}` (оба необязательны;
`after` — курсор, вернутся строки с `seq > after`; `limit` 1…1000, по умолчанию 200; всё иное отклоняется кодами, которые страница уже объясняет: `RPC-INPUT-OBJECT` (не объект), `RPC-UNEXPECTED-ARGS` (лишнее поле),
`RPC-INPUT-INVALID` (значение вне допустимого):

```
ubus call homensai-vpn probe_targets '{"after":0,"limit":200}'
→ {"version":1,"targets":["one.one.one.one","dns.google","dns.quad9.net"],"heartbeat":["1.1.1.1","8.8.8.8","9.9.9.9","other"],
   "first":812,"last":3300,"count":200,"truncated":true,"rows":[[...],...]}
```

`first`/`last` — номера самой старой и самой новой строки кольца (`last < after` значит «кольцо началось заново»); `truncated` — есть ещё.
Отвечает Lua-монитор из своего процесса (через `rpcd`-диспетчер, как `status`); если он не может — тот же ответ даёт `agent.py` из тех же
файлов, поэтому оба рантайма отдают одинаковое, и не важно, кто писал.

Набор soak: **новая копия** `private/soak-24h/cycle_router.per-target.py` (действующие файлы очереди не менялись). В конце цикла она берёт новые
строки (`per_target()`: курсор в `/tmp/soak_per_target_cursor` на роутере, страницы по 1000, до 12 страниц; сброс курсора, если кольцо началось
заново) и кладёт их в печатаемый объект цикла как `out["per_target"]` (`rows`, `first`, `last`, `cursor_before/after`, `error`).
Ошибка журнала цикл не портит. Чтобы пользоваться копией, после окончания текущей очереди указать её в `SCRIPT` файла `soak24.py`.

## 6. Стоимость

Замер в контейнере CI (Lua 5.1, Python 3.11, x86; без роутера), `router/tests/lua/bench_probe_target_log.lua`:

| Что | Контейнер CI (5 прогонов) | MT3000, оценка ×5–10 |
|---|---|---|
| запись журнала за одну пробу (2 канала: 2 строки и одно добавление в файл через `monitor_io.append`) | 124–176 мкс (медиана 136) | 0,6–1,8 мс |
| одна строка (кодирование) | 35–58 мкс | 0,2–0,6 мс |
| доля одного ядра при пробе раз в 10 с / раз в 2 с (плотные пробы) | 0,0012–0,0018 % / 0,006–0,009 % | 0,006–0,018 % / 0,03–0,09 % |
| счёт одного эхо пульса в `fast_detect.lua` (2 эхо в секунду) | 1,1 мкс | 6–11 мкс (0,001 % ядра) |
| для сравнения: `canon.encode` статуса тех же двух каналов, каждая проба | 205–370 мкс | 1–3,7 мс |
| ответ RPC: опрос новых 60 строк (кольцо 3000 строк) | 19–35 мс | 0,1–0,35 с, раз в цикл soak (≈ 5 мин) |
| ответ RPC: страница 200 строк / 1000 строк (предел) | 23–47 мс / 72–105 мс | 0,1–0,5 с / 0,4–1 с |

Контейнер работал на загруженной машине (рядом шли другие контейнеры), поэтому разброс большой; брать нужно порядок величины.
Рост кучи Lua после 20 000 проб — 83 КиБ без принудительной сборки мусора; монитор хранит только номер и размер файла.

Запись журнала на MT3000 — порядка 1–2 мс процессорного времени на пробу, то есть ≈ 0,01–0,02 % одного ядра при пробе раз в 10 с и не более
≈ 0,1 % при плотных пробах (раз в 2 с); это сопоставимо с кодированием `status.json`, которое проход делает и так, и ничтожно рядом с тремя
дочерними процессами `curl`. Счёт эхо пульса — несколько присваиваний на эхо; разница замеров `bench_fast_detect.lua` до и после (≈ 250–290
мкс на удар двух каналов, оба прогона одной машины) лежит в пределах шума. Ответ RPC читатель вызывает редко (раз в цикл soak), страница
ограничена 1000 строк, чтобы один вызов не задерживал цикл монитора надолго. Вывод: **включено по умолчанию**.Вывод: **включено по умолчанию**.

## 8. Что дальше

Данные ещё не собраны. Когда очередь soak закончится и копия `cycle_router.per-target.py` будет подключена, из `per_target.rows` считаются:
парные φ-коэффициенты целей (HTTPS × HTTPS × DNS) и вероятность «цель B упала при падении цели A», по ним — эффективное число датчиков
`n_eff` кворума и поправка гарантии `p^k`. До этого `n_eff ≈ 1,2–1,9` в `docs/PRINCIPLES-SCIENCE.ru.md` — сценарная оценка (ρ = 0,3…0,8), а не измерение.
