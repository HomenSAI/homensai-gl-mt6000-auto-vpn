# Установка с помощью ChatGPT, Codex или Claude

Если хотите, чтобы установку, настройку и проверку выполнил агент, скопируйте полный промпт ниже в ChatGPT/Codex или Claude Code(Sonnet/Opus) с доступом к терминалу и вашему роутеру. Обычный чат без инструментов сможет только объяснить шаги. Укажите адрес и желаемый результат; пароли/ключи в текст не вставляйте.

[Ручная установка](INSTALL.ru.md) · [Текущее состояние](CURRENT-STATUS.md) · [Первый запуск](FIRST-RUN-SETUP.md)

```text
МОИ ПАРАМЕТРЫ

Скачай также matching .ipk.sha256 и release-v0.9.0-verification.json. Это приложение, не прошивка. Скрипты router-test-kit бери из этого же тега, а не изменяемой main. Не заменяй более новую установленную версию старой: сообщи о различии.

ТОЛЬКО ВИРТУАЛЬНЫЕ ИСПЫТАНИЯ: если владелец явно запросил изолированный x86/OpenWrt-стенд из lab/openwrt-qemu/README.md и существует /tmp/HOMENSAI_VIRTUAL_LAB, проверяй пакет в режиме мониторинга, Auto/native выключены. Сохраняй реальную x86-идентичность. Аппаратные/firmware-пункты GL.iNet preflight отметь как неподдерживаемые в этой VM, не PASS; не запускай GL-установочный набор после его отказа. После независимой проверки всех остальных предпосылок используй обычный opkg в существующем документированном monitor-only пути VM. Не подделывай модель, не обходи native-guard и не выдавай это за приёмку GL.iNet/LAN/Auto. На реальный неизвестный роутер это исключение не распространяется.
 В этом явно выбранном VM monitor-only режиме перед обновлением старой версии проверь собственный параметр приложения monitor_only: если его нет, установи monitor_only=1 обычным UCI и проверь, что native_enabled остаётся0. Не меняй сетевую конфигурацию и не создавай фиктивную аппаратную готовность.

1. ДОСТУП И ГРАНИЦЫ
Нужны терминал на компьютере и доступ к названному роутеру. Если инструментов нет, честно сообщи: обычный чат не может выполнить установку. Недостающие адрес и способ доступа уточни одним коротким вопросом. Используй существующий разрешённый SSH и проверенный host key; новый/изменившийся ключ сначала сверь с устройством. Не отключай проверку ключей. При отсутствии SSH предложи поддерживаемую установку через LuCI и объясни требуемое действие владельца.
Пароли, VPN-ключи, токены и полные конфигурации не запрашивай в чат, не печатай, не сохраняй в Git/журналы. Используй защищённый ввод инструмента либо ввод владельцем в его панели. Не меняй сеть компьютера, Wi-Fi, адреса/маршруты адаптеров, другой роутер, WAN, DHCP или доступ из интернета. Не прошивай, не делай factory reset, не запускай посторонние службы.

2. ИСХОДНОЕ СОСТОЯНИЕ — ТОЛЬКО ЧТЕНИЕ
Проверь ubus call system board, /etc/glversion, opkg status homensai-auto-vpn, /overlay, свободную память, штатные feeds и зависимости. Зафиксируй реальный board_name/модель/прошивку, установленную и работающую версии, Auto ВКЛ/ВЫКЛ, выбранную пару/активный канал. Проверь отсутствие другого установщика, незавершённого rollback/транзакции, собственного guard и несохранённых изменений.
Architecture:all или выбор модели в UI не доказывают совместимость. Непрерывный Auto проверен на отдельно подготовленном GL-MT3000/GL.iNet4.11.0; текущая приёмка MT6000 continuous mode и произвольной прошивки не заявлена. Не обходи реальные platform/readiness-отказы.
 Проверь саму файловую систему настроек (/etc/config или её смонтированный overlay), а не только число свободных байт: изучи statvfs/proc mounts и доступность записи. Read-only система может иметь много места. До записи пакетов/настроек остановись и диагностируй её; не перемонтируй и не исправляй файловую систему рабочего роутера автоматически.

3. ПРОВЕРЕННОЕ ВОССТАНОВЛЕНИЕ
До изменений получи поддерживаемый экспорт конфигурации и нужные настройки/историю приложения. Сохрани зашифрованную приватную копию вне Git, защити ключ средствами ОС либо отдельным защищённым хранилищем. Проверь состав архива, обязательные файлы, SHA256 и независимую расшифровку/чтение в памяти. Не сохраняй открытые секретные конфигурации в рабочем проекте. Без проверенного восстановления установку не продолжай. Конфигурационный экспорт не является полной копией flash/загрузчика.

4. ЗАВИСИМОСТИ И ФАЙЛЫ
Проверь python3, lua, lua-cjson, libuci-lua, ip-full, ubus, rpcd, luci-base, ca-bundle. Недостающее устанавливай обычным opkg только из исходных vendor feeds этой прошивки. Не запускай массовый opkg upgrade, не меняй feeds, не ставь пакеты чужого выпуска, не используй force. Сначала проверь место; текущий preflight требует минимум20МиБ свободного записываемого пространства. При конфликте ABI/подписей/зависимостей объясни точную причину и останови зависимые изменения, не удаляй системные компоненты ради обхода.
Скачай пакет/checksum/verification JSON из одного HTTPS-релиза. Проверь имя, размер, SHA256 на компьютере и после передачи на роутер. Сверь с checksum, записью релиза и EXPECTED_SHA/SIZE в02-install.sh того же тега. При несовпадении не устанавливай. Не выполняй скачанный скрипт через pipe в shell.

5. УСТАНОВКА
При обновлении штатно останови Auto и дождись завершённого rollback/очистки. ACK/queued не равно завершению. Не удаляй журналы/guard, не сбрасывай лимиты и не обходи lifecycle-отказ. Прочитай и выполни01-preflight.sh из того же тега; он пишет только свой отчёт в/tmp. Исправь допустимые причины отказа и перепроверь. Затем02-install.sh с проверенным IPK либо обычный opkg install /tmp/homensai-auto-vpn_0.9.0-1_all.ipk по инструкции. Это не Flash Firmware; exit0 от opkg недостаточно.
Выполни03-verify.sh wait. Проверь установленную0.9.0-1, работающий RPC0.9.0, свежие данные, отсутствие service errors, единственный монитор и нужные службы. Где доступно, сравни установленные файлы/права и реально отдаваемые dashboard/CSS из выбранного пакета с payload проверенного пакета. Непроверенные области перечисли. Старый RPC/кеш LuCI диагностируй штатно; не делай вывод по одной версии opkg.

6. ПЕРВЫЙ ВХОД И ПАРА
Открой Services → HomenS.AI Auto VPN, Ctrl+F5. Соглашение показывается только до первого принятия текущей версии. Галочки и «Принять» выбираю я; не вызывай terms_accept и не записывай terms_version за меня. Уже сохранённое принятие не сбрасывай: пропуск соглашения при повторном входе нормален.
Далее объяснение с тремя схемами → OK → восемь шагов: язык/оформление, мониторинг, существующие VPN, имена/приоритеты, восстановление, скорость, Telegram, обзор. Пара выбирается в «Настройки → Все настройки приложения → шаг3: Существующие VPN». Основной — обычный предпочитаемый канал; резервный — другой существующий рабочий профиль на случай отказа. Покажи значения до сохранения. Не путай профиль, Connected-туннель и реально выбранный маршрут. Профили/ключи создаются в штатной панели GL.iNet: не выдумывай их. Если их нет, сохрани честный результат «приложение установлено, пара не настроена».
Необязательные настройки сохраняй прежними без моего выбора. Не отправляй Telegram-тест без запроса. Сохранять разрешённую проверенную конфигурацию можно инструментами; затем проверь чтением, а не только ACK. Save не принимает соглашение и не запускает Auto. Если я откладываю мастер, зелёная кнопка открывает панель с текущими настройками, не сохраняет черновик, не сбрасывает и не включает Auto; это не завершённая настройка пары.

7. AUTO И ТЕСТЫ
Установка приложения не равна готовности переключать. Прочитай актуальную подготовку платформы и реальные проверки DNS/ускорения/vendor/rollback. Модель, загруженный модуль и сохранённый флаг не являются доказательством. Если нужны изменения DNS/ускорения/stock VPN startup, покажи конкретный объём и отмену: обычная установка их не разрешает. Не отключай работающего DNS-владельца по чужому примеру и не выгружай модули принудительно.
Если я выбрал «включение Auto», текущая платформа готова и соглашение принято мной, выдай один обычный Start. Дождись завершения STARTING, подтверждённого выбранного канала и свежих DNS+двухHTTPS для обоих VPN. Очередь, зелёная кнопка, интерфейс туннеля и Connected сами по себе трафик не доказывают.
В router-probed-ipv4 режиме подготовленного MT3000 постоянно запущенный LAN-помощник не требуется. Дополнительная LAN-проверка доказывает путь реального компьютера через роутер. Агент может выполнить её лишь с устройства этой LAN; облачный ChatGPT/Claude без такого доступа не заменяет клиент. Не подделывай подтверждения. Испытание с переключением требует определённого времени/предела, возврата и разрешения на прерывание сеансов. Без этого выполняй только чтение/проверку без переключения. Не меняй сеть компьютера для обхода ошибки привязки.

8. ИТОГ
Сравни защищённые настройки до/после. Неожиданные изменения расследуй; восстанавливай только свои подтверждённые изменения, не затирая новые правки владельца. Не сбрасывай firewall целиком. Отчёт: модель/прошивка; установленная/работающая версии; источник/размер/SHA256; зависимости; копия/проверка/восстановление; интерфейс/монитор; выбранная пара/активный канал; Auto ВКЛ/ВЫКЛ; изменения; непроверенное; URL панели; Stop/удаление/восстановление. Разделяй PASS/FAIL/PARTIAL/BLOCKED/SKIPPED/UNKNOWN по фактам. После перезапуска нужен явный Start.
Не приписывай установленной версии чужие тесты, router-only проверке — LAN-доказательство, короткому прогону — сутки. Не обещай IPv6/MT6000 continuous mode/физическое питание/автономную эксплуатацию без реальной проверки. При блокере сохрани точку остановки и следующий безопасный шаг вместо выдуманного успеха.
```

Владелец предоставляет доступ, лично принимает первое соглашение и выбирает спорные параметры. Остальные разрешённые действия выполняет агент. Уже сохранённое принятие соглашения не сбрасывают.
