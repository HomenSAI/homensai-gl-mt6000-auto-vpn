## Действия / Actions

| Действие / Action | Реальный результат / Effect |
|---|---|
| Проверить сейчас / Check now | Запрос свежих наблюдений; не выбирает маршрут / Requests observations without selecting a route |
| Сохранить (мастер или раздел настроек) / Save (wizard or a settings section) | Собственные параметры приложения; не принимает условия и не включает Auto / Own app preferences, no terms acceptance or Auto start |
| Включить Auto / Turn Auto on | Явный управляемый запуск подготовленного режима; ждите подтверждения / Explicit prepared-mode start, await confirmation |
| Переключить сюда / Switch here | Запрос выбранного канала с актуальными проверками; ACK не завершение / Guarded channel request, ACK is not completion |
| Выключить Auto / Turn Auto off | Отмена ожидающего запуска и управляемое восстановление; итог проверяется / Revokes pending start, managed recovery must be verified |
| Тест сбоя / Failure test | Ограниченный сбой текущего туннеля, проверка другого маршрута; «Остановить и снять сбой» снимает его досрочно / Bounded current-tunnel fault and alternate-route check; "Stop and remove fault" ends it early |
| Служба мониторинга / Monitoring service | Независимые измерения; часы журнала не ускоряют сетевые пробы / Independent measurements, log clock does not accelerate probes |

Два клиента выбираются на шаге 2 «Каналы» мастера или в «Настройки → Каналы: основной и резерв». Для другой привязки сервера/протокола сначала используйте штатную панель GL.iNet → VPN, затем обновите страницу Auto VPN и дождитесь согласованной идентичности. Не меняйте штатные профили во время управляемого перехода. / The two clients are chosen in wizard step 2 (Channels) or in Settings → Channels: primary and reserve. For another server/protocol binding use the stock GL.iNet → VPN panel first, then reload the Auto VPN page and wait for a consistent identity. Do not change stock profiles during a managed transition.

Storage controls are in Settings → History and memory (Console: System tab): live log entries 1–2000, detailed history 1–7 days; they change with Auto off. Preserve existing values by default. Settings → System and diagnostics → Monitoring service → Service parameters and router features sets the probe interval, the statistics checkpoint and the profile limit per round (1–16); the wizard keeps supported saved values up to 32. For a selected pair, 2 is a useful starting limit; it does not activate stopped profiles by itself. / Хранение: «Настройки → История и память» (в «Пульте» — вкладка «Система»): записей в живом журнале 1–2000, подробная история 1–7 дней; меняются при выключенном Auto. Интервал проверки, checkpoint и лимит профилей за раунд (1–16) — в «Служба мониторинга» → «Параметры службы и функции роутера».

Для подтверждённой остановки проверяйте фазу/guard/восстановленный или удержанный маршрут. `STOPPED-ON-RESERVE` не означает успешный возврат исходного пути. [Аварийные команды](../router-test-kit/EMERGENCY.md) — осознанное восстановление, а не обычное чтение.

## Как быстро переключать / How fast to switch

**Settings → How fast to switch** (Console: Auto tab) offers the presets Calm, Normal (default) and Fast and, under Custom values (11 parameters), edits check interval (10–300 s), source failures (2–10; counted only by the "Previous rule" detector, with the default HMM detector the model decides), reserve successes (2–10), cooldown (60–1800 s), minimum dwell (60–3600 s), forward attempt limit (1–10) and rolling window (1–15 minutes), primary return successes (2–10), primary stability (30–600 s), primary stability after a failed reserve (0–60 s, 0 = the full primary stability), and the return policy (return to primary automatically / stay on the working reserve). It also holds Allow a brief drop of calls and downloads and the fast switch (no GL rebuild). The Default values button restores 10 s / 3 / 2 / 60 s / 60 s / 3 per 15 minutes / 2 over 120 s / 10 s after a failed reserve / healthy-primary return (120 s and 10 s since 03.11.2026, [design note](architecture/RESCUE-STABLE-2026-11-03.ru.md)). Existing saved values survive upgrade.

«**Настройки → Как быстро переключать**» (в «Пульте» — вкладка «Auto»): наборы «Спокойно», «Обычно» (по умолчанию), «Быстро» и «Свои значения (11 параметров)»: интервал 10–300 с; ошибки основного 2–10 (считаются только детектором «Прежнее правило»; при HMM по умолчанию решает модель); проверки резерва 2–10; пауза 60–1800 с; пребывание 60–3600 с; 1–10 попыток за 1–15 минут; проверки основного 2–10 и стабильность 30–600 с; стабильность основного при отказавшем резерве 0–60 с (0 — полная стабильность); политика возврата («Вернуться на основной автоматически» / «Оставаться на работающем резерве»). Там же «Разрешить короткий обрыв звонков и загрузок» и быстрое переключение без перестройки GL. Кнопка «Значения по умолчанию» восстанавливает 10 с / 3 / 2 / 60 с / 60 с / 3 за 15 мин / 2 за 120 с / 10 с при отказе резерва / автоматический возврат (120 с и 10 с — с 03.11.2026). Уже сохранённые настройки при обновлении не сбрасываются.

The attempt limit never stops Auto from leaving a failed primary. From the failover that reaches the limit within the window, each further one doubles how long the primary must be stable before the return (up to 10 minutes); the hold shrinks as failovers leave the window ([flap damping](architecture/FLAP-DAMPING-2026-11-02.ru.md)). When the reserve carrying the traffic fails itself, the primary is taken back after the shorter stability after a failed reserve (default 10 s) without that hold. After the owner's Stop the autostart flags that preparation turned off go back to their saved values, so the GL VPN dashboard manages the tunnels again; with Auto off and a selected tunnel down the Auto lamp says that Start brings the pair up. / Лимит попыток никогда не мешает уйти с упавшего основного. Начиная с ухода, достигшего лимита в окне, каждый следующий удваивает время стабильности основного перед возвратом (до 10 минут); по мере выхода уходов из окна время сокращается. Если отказал сам резерв, который везёт трафик, основной возвращается после короткой стабильности при отказе резерва (по умолчанию 10 с), без этого удержания. После Stop владельца флаги автозапуска, выключенные подготовкой, возвращаются к сохранённым значениям, и туннелями снова управляет VPN Dashboard GL; если Auto выключен, а выбранный туннель не поднят, лампа Auto подсказывает, что пару поднимает Start.

Large packets: the monitor also checks every 5 minutes (on every check while a hole is seen) that packets of the tunnel MTU pass; a tunnel that passes the small checks but loses all large ones reports VPN-MTU, which counts as a failure, so Auto prefers the other tunnel when it passes. TCP MSS on the tunnels is already clamped by the GL firewall zones. Optional SQM (cake) on the tunnel egress is off by default and is switched on only by SSH (`sqm_enabled`, `sqm_upload_kbit`) ([design note](architecture/MTU-SQM-2026-11-03.ru.md)). / Большие пакеты: монитор раз в 5 минут (а пока видна «дыра» — на каждой проверке) проверяет, что пакеты размером с MTU туннеля проходят; туннель, который проходит малые проверки, но теряет все большие, получает VPN-MTU — это сбой, и Auto предпочитает другой туннель, если тот проверку проходит. TCP MSS на туннелях уже ограничивают зоны брандмауэра GL. SQM (cake) на выходе туннеля по умолчанию выключен и включается только по SSH.

Failure detector (`failure_model`, expert: **Settings → System and diagnostics → Expert: failure detector and server pick**, field «Failure detector»): **Standard** (default) leaves a channel only when a 6-state model says the failure will last at least 20 s more with probability ≥ 0.8 — about 25 s into a long outage, never for 15–20 s blips, not for ≤ 20 % loss, yes for ≥ 40 %; **Fast** (θ 0.7) leaves at about 21 s but also on most 20 s blips; **Previous rule** = «failures in a row» above. In the model modes a planned return from a healthy reserve also needs the primary healthy by the same model (P(healthy) ≥ 0.90, or 300 s of healthy checks), which stops flapping on a primary that keeps losing ~30 %; a return from a reserve that has failed itself is never delayed by it (only the stability after a failed reserve applies) ([design note](architecture/HMM-DETECTOR-2026-11-03.ru.md)). The same expert block chooses how the best server inside a channel is picked (`server_pick_model`): **Simple** (default, the 20 % rule) or **Bayesian** (fewer useless changes and probes, slower to find a better server). / Детектор сбоя (`failure_model`, эксперт: «**Настройки → Система и диагностика → Эксперт: детектор сбоя и выбор сервера**», поле «Детектор сбоя»): **Стандартный** (по умолчанию) уходит с канала, только когда модель из 6 состояний оценивает, что сбой продлится ещё ≥ 20 с с вероятностью ≥ 0,8 — примерно через 25 с долгого обрыва, никогда на сбоях 15–20 с, не при потере ≤ 20 %, да при ≥ 40 %; **Быстрый** (θ 0,7) — примерно через 21 с, но и на большинстве сбоев 20 с; **Прежнее правило** — «сбоев подряд» выше. В режимах модели плановый возврат со здорового резерва также требует здоровья основного по той же модели (P(здоров) ≥ 0,90 или 300 с здоровых проверок) — это убирает «качели» на основном с постоянной потерей ~30 %; возврат с резерва, который сам отказал, этим условием никогда не задерживается (действует только стабильность при отказавшем резерве). Там же выбирается способ подбора лучшего сервера в канале (`server_pick_model`): **Простой** (по умолчанию, правило 20 %) или **Байесовский** (меньше лишних смен и проб, но лучший сервер находится медленнее).

The rules change with Auto off: when Auto is on, saving offers "Stop Auto and save" and waits for the confirmed stop; saving changes only the application settings and never starts Auto again. Attempt history is retained for the full maximum window, even when a shorter window is chosen, so changing the policy or starting a new session does not erase attempts. / Правила меняются при выключенном Auto: при работающем Auto сохранение предлагает «Остановить Auto и сохранить» и ждёт подтверждённой остановки; сохранение меняет только настройки приложения и само Auto снова не включает. История попыток сохраняется за полный максимальный период, даже если выбран более короткий; изменение правил и новый запуск её не стирают.

WAN-DOWN: если у роутера нет интернета (собственное эхо через порт WAN, вердикт kmwan, линк WAN, проба обоих каналов), Auto удерживает текущий маршрут и не уходит на резерв; после возврата WAN ждёт до `wan_recover_grace` с (30; 0 — без ожидания) здоровой пробы основного (WAN-RECOVERING). Если резерв отвечает, удержания нет. Формат `/proc/gl-kmwan/config` и поведение при реальном отключении WAN на MT3000 ещё не проверены. / WAN-DOWN: when the router itself has no internet, Auto keeps the current route and does not move to the reserve; after WAN returns it waits up to `wan_recover_grace` seconds (30; 0 = no wait) for a healthy primary probe.
