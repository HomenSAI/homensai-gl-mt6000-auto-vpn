# Channel/graph display contract

| Context | Meaning |
|---|---|
|Every channel lamp, both views (Simple and Console, page from 03 Nov 2026)|Green = the channel works; the chip "Traffic here" marks the one carrying traffic, "Standing by" the other; yellow = a check or a switch; red = not responding or tunnel off (with code); grey = no fresh data.|
|Manual route control|"Switch here" appears only on the card that does not carry traffic; the status shows the switch until the router confirms it. A manual switch never turns Auto off.|
|Two indicators — owner rule 07.11.2026 (replaces the single program lamp of commit 15f38bc8 and the earlier "yellow = reserve in use")|**(1) Main traffic light** (big status lamp, Home hero / Console strip) = `overall()` in router/ui/core.js, **only about the internet**. Green = there is internet, through the primary or the reserve, whether Auto is on or off ("Internet works" / «Интернет работает»; on the reserve "Works via the reserve" / «Работает через резерв», the line says there is no spare channel until the primary is back, the reserve card keeps "Traffic here", the primary card shows its own failure; the line also names the Auto state). Yellow = a channel transition: a route switch (APPLYING / switching), a channel or route check, or the carrying channel proven failed while Auto is on and about to switch. A speed test is not a transition of the internet (owner 07.11.2026): the main light stays green "Internet works" with the line "Speed test running…" / «Идёт тест скорости…», and the Auto indicator is yellow. Red (✕) = no internet proven: both channels proven failed, the router's own WAN check says WAN-DOWN, the carrying channel proven failed while Auto is off (nobody switches), or the carrying channel still failed 60 s (`FAIL_WINDOW`) after it was first seen failed while Auto is on ("No internet" / «Нет интернета»). The status has no per-channel "failed since" timestamp, so the 60 s window is a page-local timer in the status clock, started when the page first sees the failure and reset when the channel is not failed (a reloaded page starts it again). Starting/stopping Auto does not make the main light yellow; Auto stuck does not change it. Grey (?) = no fresh data (stale controller, no answer, stale carrying-channel check, setup not finished). **(2) Auto indicator** = `autoIndicator()`; the Auto switch track takes its colour from it (`data-sig`) and the switch shows its words and icon. Green = Auto is on ("Auto is on" / «Auto включён»), also while it handles a failed channel. Red ○ = manual mode ("Manual mode (Auto is off)" / «Ручной режим (Auto выключен)»). Red ⚠ = Auto stuck: HELD, BLOCKED, pair recovery required and every other controller problem ("Auto stopped: recovery needed" / «Auto остановлен: нужно восстановление»); details in the line under it. For a stuck Auto the state line under the switch and the header tooltip carry the exact reason and code (`stuckReason()`: HELD, BLOCKED/RELEASE-PENDING/…, the light code and the blockers). Yellow = Auto is starting / stopping / paused for a speed test. Grey ? = no fresh data or the Auto state is not confirmed yet. "Busy" or "checked" alone no longer colour the track. Unknown or stale evidence is never green and never red on either indicator; colour is never the only carrier (words in RU/EN, icons ✕ ○ ⚠ ?; the main lamp's accessible name includes its title, the Auto lamp's its words). Blinking is unchanged (green 2.4 s, yellow 1 s, red 1.4 s, grey still; none with reduced motion). Channel lamps are unchanged. AUTO_SIGNAL_TABLE (`autoState()`) still feeds the legacy page's own Auto light. **Header pair** (every page: Simple, Console, wizard): a small "Internet" / «Интернет» lamp (`overall()`) and an "Auto" lamp (`autoIndicator()`, the same colour as the Auto switch track), with visible labels; the accessible name starts with the label and includes the words, the tooltip carries the words and the line. The lamps are not controls. On a phone (≤ 760 px) they take their own full-width header row. Table test: router/tests/test_program_lamp_ui.js.|
|Current VPN checks|Healthy is green (selected or standby, told apart by the chip); failure red; missing evidence grey/unconfirmed.|
|M/R transition diagram (legacy page, tag ui-original-2.1.0-alpha6)|M main left, R reserve right; arrow gives direction. A switch in progress is yellow, confirmed selected green/other red.|
|Standalone failure/recovery event|Only the event-time role is colored failed/recovered; no switch/other health is invented.|
|Failure episode chart (legacy page)|Blue main/orange reserve, with old missing-role records disclosed separately rather than a third invented channel.|
|Pinned service monitor (legacy page)|Monitor/Auto first; working channel above waiting/failed, retaining role labels.|
|Role cards|Primary always left/top, reserve right/bottom, in both views.|

Freshness uses router-observed time plus elapsed browser time. Queue ACK is not completion; stale data expires. Two Connected tunnels do not prove two simultaneous selected common routes or external-client connectivity. [Event provenance](CHANNEL-ATTRIBUTION.md) · [Behavior](HOW-IT-WORKS.en.md).
