# Full project review, 28 October 2026 (0.9.1-alpha48)

Three independent read-only reviews (router backend, web UI, tooling/tests/docs). The top findings were checked in the code before this report. Status column: **fixed in alpha49** or **open**.

## Errors

| # | Finding | Status |
|---|---------|--------|
| E1 | Statistics reset wiped native/speed history on disk before writing the archive; a corrupt speed history crashed the monitor | fixed in alpha49 |
| E2 | Native history written by supervisor and reset without a shared lock, through one shared `.pending` file | fixed in alpha49 (lock, unique temp files; also `atomic_json`) |
| E3 | History/certificate write failure after COMMITTED rolled traffic back to the failed primary | fixed in alpha49 |
| E4 | One transient error held a running session for good; a second one switched Auto off | fixed in alpha49 (resume after a verified tick) |
| E5 | A clock stepped backwards stopped history recording and the retry budget | fixed in alpha49 (clamped) |
| E6 | "Auto works" counted pause and pending start; channel cards ignored whether Auto runs | fixed in alpha49 |
| E7 | A route switch inside running Auto was shown as "Turning Auto on" and spoiled the countdown | fixed in alpha49 |
| E8 | A lost Start/Stop answer left the button pending forever | fixed in alpha49 (AUTO-CONTROL-UNCONFIRMED after the deadline) |
| E9 | Page render errors were reported as RPC-UNAVAILABLE | fixed in alpha49 (UI-RENDER-FAILED) |
| E10 | During an outage the page clock froze, so old data looked fresh | fixed in alpha49 |
| E11 | English-only technical notices, uncatalogued UNKNOWN / UI-ACTION-FAILED, other VPNs called "reserve" | fixed in alpha49 |

## Weak points (open)

| # | Finding |
|---|---------|
| W1 | Supervisor parses up to 2.3 MB of history on every publish; status RPC re-reads history and runs uci per call |
| W2 | Telegram delivery runs inside the monitor loop (up to 15 s per job) |
| W3 | Live chart polls every 2 s (python per call); the page rebuilds all pages every 10 s; error-link scan runs on every DOM change |
| W4 | Focus and screen-reader announcements are lost or repeated on every 10 s rebuild |
| W5 | 1.2 MB page with help, training and the error catalogue always loaded; no gzip on uhttpd |
| W6 | Two processes may write pair-auto-state.json (now torn-file safe, lost update still possible) |
| W7 | Stop runs a Lua subprocess while holding the control lock |
| W8 | Unused modules shipped (cascade_*, candidate_runtime, configuration_migrations); minimum_* UI sources are tested but not built |

## Engineering process (open)

| # | Finding |
|---|---------|
| P1 | `.git/handoff` holds 15 GB of recreatable CI tars and full-history bundles; nothing prunes it (needs the owner's approval to delete) |
| P2 | The UI is built by ~240 text patches on a frozen alpha12 file; ~110 are not asserted; CI does not compare a fresh build with the committed module |
| P3 | 116 old dashboard files, 80 css files and 77 ipk binaries are committed; each release adds ~2.2 MB |
| P4 | Each release needs a manual UI module rename, a package-record commit and a second 30-40 min CI run; Gitea save bundles the full history (180 s timeout) |
| P5 | README is stale (says alpha21) and partly corrupted; handoff CURRENT.md is 189 KB of history; several "current" handoff files date from 24 Oct |
| P6 | tools/tests and lab tests never run in CI; the CI images have no Dockerfile in the repo for the 3.11 image; receipts are not checked for the Lua run |
| P7 | `Installed-Size` in the ipk control file is the compressed size |
| P8 | Publication accepts only alpha tags |

## Strengths

Strict RPC decoding, no shell injection; checksummed storage with backups and O_NOFOLLOW; kernel-timeout safety nets and a journal-first transaction; reproducible package builds checked on two runtimes; isolated CI; guarded publication; a large error catalogue linked from every code.
