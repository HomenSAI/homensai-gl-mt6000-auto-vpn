## Дополнительные воспроизведённые причины

1. **Ответ RPC продлевал срок старого доказательства.** При доставке готового status с задержкой 24 секунды UI начинал отсчёт от получения. Просроченные kernel evidence, heartbeat и оба website response снова показывались свежими. Теперь возраст включает всю длительность запроса по монотонным часам; исходные router timestamps не меняются. Получение ответа само по себе не подтверждает маршрут.
2. **Новая вкладка теряла объяснение после обратного хода часов.** Backend сохраняет terminal timestamp не меньше времени запроса, поэтому корректный CANCELLED/REFUSED мог оказаться «в будущем» и исчезал из UI. Для корректного request ID такой результат виден максимум 300 монотонных секунд с первого наблюдения на странице. Повторный перевод часов не продлевает это время, а presentation tick снимает сообщение без нового RPC. Это сообщение не разрешает переключение и не завершает чужую локальную команду. Отдельно устранено перекрытие нового backend result из другой вкладки старым saved отказом: при двух разных корректных request IDs временные метки не задают порядок команд. Локальный отказ без request ID сохраняет прежний временной fence.
3. **Кнопки обещали заведомо запрещённое переключение.** `pair_manual.controls()` уже получал отрицательное подтверждение ядра, но разрешал routing choices; строгий consume затем отказывал. Теперь известное невалидное, не repairable-missing ядро сразу даёт `KERNEL-POLICY-UNVERIFIED` у обоих направлений. Допуск repairable-missing и Resume сохранён; поздняя проверка consume обязательна.
4. **Не было доказательства конкретного незавершённого шага UCI.** При выбранных правилах через третье generic rule требуются несколько moves. После первого move прежний retry отвергал собственный промежуточный порядок. После последнего move до commit он пропускал commit, а синхронизация Lua отказывала из-за pending delta. Новый checkpoint записывается до конкретного шага; проверяются его точные before/after и принадлежность каноническому минимальному плану. Произвольные перестановки не разрешаются. Повтор commit требует собственного нового checkpoint.

5. **Forward RTP отказал до изменения ядра.** Настоящая цепочка public manual request → consume → native child → Linux/Lua оставляла UCI в after, а ядро — точно равным записанному kernel_before_fingerprint. Прежний recovery не использовал это существующее оригинальное доказательство. Теперь отдельное promotion допускается только после OFF fence, с полным прежним proof и повторными live bindings/guard/revision/CAS проверками. restore_order_origin задаёт начало UCI-плана, а restore_before_order сохраняет действительно подтверждённую роль ядра. Восстановление неизменившегося маршрута не объявляет вымышленную смену канала. Новый focused набор: 23/23 PASS; manual controls: 31/31 PASS. Старое неизвестное состояние без доказательства этим путём не разрешается.

## Область дополнительной проверки

Новый delayed-status сценарий воспроизведён настоящим Chromium на asset alpha58. Итоговый alpha59 dashboard имеет **879458 байт**, SHA256 `ec7f62847a5ea87d6fbcd995a4088d2d282bb3826e0d9504519e0e081d7181a0`, проходит прежний предел 879512,2 байта. Первый целевой браузерный прогон прошёл 12/12 assertions; после дополнительной правки cross-tab feedback итоговый asset проверяется отдельно: полный экран, боковая панель, «Минимум», оба отклика, отсутствие переключающих RPC и ошибок JavaScript. Он использует явный synthetic RPC overlay и не является новым подтверждением физического VPN.

Воспроизведение rollback дополнено настоящими дочерними процессами и SIGKILL после первого и последнего UCI moves. Проверяется неизменность настоящего гостевого ядра QEMU/OpenWrt и последующее выполнение production recovery. UCI/vendor compiler/guard/health в этом стенде остаются адаптерами; эта граница не должна исчезнуть из машинного отчёта. Старые 20 model-filesystem crash cases относятся к своему lab helper и не подменяют этот новый сценарий.

Окончательные новые backend результаты, immutable offline matrix, package hash и перечень evidence будут закреплены отдельной записью после замораживания исходника. Предыдущие 1178 application tests на Python 3.9/3.11 и 70 browser/kernel assertions остаются доказательствами alpha58, а не автоматически нового исходника.

## Незакрытые условия выпуска

Точные локальные Docker images утверждённого runner в этой среде отсутствуют. Также недоступны Docker/Podman/OCI runtime, PowerShell и делегированные cgroups. Один image строится из прежних локальных image IDs; новая сборка с неприкреплённым apt или другой portable Python не воспроизводит его байты. Нужен существующий утверждённый runner либо проверенные exports с отдельным согласованным изолированным runtime. Локальные совместимые среды не выдаются за этот gate.

Приватный runbook и `private/ACTIVE-EXECUTOR.local.json` отсутствуют; физический MT3000 не опрашивался. Штатные RTP/procd, настоящие VPN/LAN, установка, разрешённый Start, зашифрованные before/after backups и публикация assets с независимым скачиванием остаются аппаратной и выпускной приёмкой. Primary MT6000 и Windows networking исключены. До закрытия обязательств из настоящего основного handoff: только отдельная ветка и draft PR, без release/install/main merge.
