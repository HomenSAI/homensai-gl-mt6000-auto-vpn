# TLA+ cross-check of the formal model / Сверка TLA+ (TLC) с model.py

`Supervisor.tla` is an independent TLA+ re-statement of the pair-mode supervisor model `tools/formal/model.py`.
TLC (TLA+ Tools 1.7.4) explores it exhaustively; this directory lets the offline CI compare the TLC result with the
Python model, so that **editing `model.py` without the matching edit of `Supervisor.tla` (or the other way round) turns the
check red**. The comparison is exact: number of distinct states, number of transitions, every violation signature with
its count (`LEAK:*`, `TRANSITION:*`, `INCONSISTENT`) and the supervisor edges per program counter before and after (`STEP:*`: an edge
that moves to another reachable state changes no other count). An edge moved inside one pair of program counters stays invisible. The spec follows the model with the rules G1-G7, K12, F32/T4A (07.11.2026) and the options
`--fast-switch` (constant `FastSwitch`) and `--key-pin` (constant `KeyPin`, the action `ActKey`). TLC and `model.py` agree exactly on one configuration per profile of `ci_check.py`:

| restart-allfix | `--no-gl` | 245 584 | 1 719 852 |
| faults-allfix | `--no-gl --no-power --faults` | 128 720 | 755 090 |
| faults-power-allfix | `--no-gl --no-crash --faults` | 115 984 | 735 866 |

`keys-blocker-allfix` (`--key-pin blocker`, the code before the fix: 478 112 states, 3 396 326 transitions before F32/T4A, not re-run since) also agreed; it is not part of
the gate and runs by name: `tlc_check.py --only keys-blocker-allfix`.

The bounds are exactly those of `ci_check.py`, none is reduced further, so no separate full TLC run is needed for them. What TLC
does not compare in CI: the liveness checks and EF-START of `model.py` (they need the dumped state graph; the private study does that)
and the "everything on" profile of `run_full.sh`. The options of other branches that the spec does not state yet are listed in
`gen_cfg.py` `NOT_RESTATED`; any other profile of `ci_check.py` without a cfg is red. The full study
(14 configurations, liveness, counterexample traces, report) stays in the private working tree `private/math/formal-tlc`.

The check is **optional**. Without docker or without the image it reports `SKIPPED` (not failed) and the CI stays green.
Nothing here touches a router.

## What is here

| file | purpose |
|---|---|
| `Supervisor.tla` | the spec (copy of the verified study spec) |
| `cfg/*-allfix.cfg` | TLC configurations, generated by `gen_cfg.py` (same profiles and fix set as `ci_check.py` / `expected.json`) |
| `gen_cfg.py` | writes the cfg files; reduced copy of the study generator |
| `py_census.py` | counts states, edges and violating edges of `model.py` (its own JSON truncates the lists) |
| `tlc_check.py` | the check: runs TLC in docker and `py_census.py`, compares, prints `TLC-CROSSCHECK {json}` |
| `SHA256SUMS` | hashes of the mirror files above (line endings normalized); a unit test fails if one is edited without `--update-manifest` |
| `TLA2TOOLS.sha256` | pinned sha256 of `tla2tools.jar` |
| `Dockerfile` | `eclipse-temurin:21-jre` + the jar, sha256 verified at build time |
| `../../../scripts/build-tlc-image.ps1` | builds the image `homensai-tlc:local` |
| `../../tests/test_tla_crosscheck.py` | unit tests of the comparison with fake TLC output (always on, no docker) |

The jar is **not** stored in git and **nothing is downloaded at CI time**.

## Build the image once per machine

```powershell
# the script finds private/math/formal-tlc/tools/tla2tools.jar (or private/tools/) in the main checkout:
powershell -File scripts/build-tlc-image.ps1
# or give the jar explicitly / fetch the official v1.7.4 release once:
powershell -File scripts/build-tlc-image.ps1 -JarPath C:\path\to\tla2tools.jar
powershell -File scripts/build-tlc-image.ps1 -Download
```

The script verifies the jar against `TLA2TOOLS.sha256` (`936a2620...e88`), the Dockerfile verifies it again, and the image
carries the label `org.homensai.tla2tools.sha256`; `tlc_check.py` refuses an image whose label differs.

## How it runs

`scripts/offline-ci.ps1` runs it on the host (TLC needs docker, the isolated CI containers have none) on the committed
snapshot, before the containers: `python tools/formal/tla/tlc_check.py --source <snapshot> --py-image <python image>`.
Two configurations run at a time (`--jobs`), each one a TLC container with 3 workers and a `model.py` container (`--network none`,
read-only, all capabilities dropped, source mounted read-only). The whole check has a limit of **1500 s** (`--timeout`); on a timeout
the containers started by the run are killed and the result is `FAIL`. The result JSON is mounted into the CI containers and
`qa/run_offline_ci.py --tlc-result` records it in the receipt: `tlc_crosscheck` is `PASS`, `SKIPPED` (with
`tlc_crosscheck_reason`) or `NOT-RUN` (the script was started without a result), plus `tlc_crosscheck_seconds` and
`tlc_crosscheck_states`. Skip it explicitly with `scripts/offline-ci.ps1 -SkipTlc`. Typical time: about 14 min on a shared 8-CPU machine (the two old configurations alone took about 1.5 min).

Stand-alone: `python tools/formal/tla/tlc_check.py [--py-image IMAGE] [--only held-allfix] [--result out.json]`
(exit 0 PASS/SKIPPED, 1 FAIL). Offline part only: `--verify-manifest`.

## When the check is red

`states differ` / `transitions differ` / `violation signature X differs`: the two models no longer describe the same system.
Decide which one is right, then change **both** in the same commit:

1. edit `model.py` and `Supervisor.tla` (the spec keeps the same action names and fix switches: `Fixed`, `K11`, ...);
2. if the set of fixes changes, also `ALL` in `gen_cfg.py` and `expected.json` `"fixed"` (a unit test compares them);
3. `python tools/formal/tla/gen_cfg.py` (when the profiles changed) and `python tools/formal/tla/tlc_check.py --update-manifest`;
4. `python tools/formal/tla/tlc_check.py --py-image homensai-vpn-python311:local` must print `EQUAL` for every configuration.

A new option of `model.py` with a CI profile: add a constant to `Supervisor.tla`, the option to `py_census.py` `model_cfg`, the profile to
`gen_cfg.py` `PY_ARGS` and its switch to `tla_constants`, then the steps above. Until then name the profile in `NOT_RESTATED`.

`TLC reports violated invariant(s) TypeOK/Census` means the spec itself is broken. `wrong TLC image` means rebuild the image.
