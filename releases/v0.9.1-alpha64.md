# Auto VPN 0.9.1-alpha64

Alpha64 removes the red/green flicker of the status indicators and makes switching and recovery lighter on the GL-MT3000. It contains all alpha60–alpha63 fixes.

Measured on the router before this release: a status call, which the page polls every 10 s, took 5–7.5 s and returned 424 KB. The load average was about 2 on two cores. Data aged past the 30 s window, so the page alternated between "stale" (red) and "working" (green).

Status and display:
- The manual-control availability reuses one kernel attestation for 15 s in RAM, keyed by the journal and the policy order. It skips the attestation entirely during a switch. Every manual dispatch still re-attests from scratch.
- All freshness checks use one display tolerance: the router's window plus 25 s for probe time, the 10 s poll and a slow status call.
- "No fresh data" is never shown as "no VPN works".
- The channel card no longer shows a leftover "ms · HTTPS" label, and a healthy channel is no longer "waiting for the first router check".
- LuCI's own "Refreshing" badge is hidden on the app pages.
- Superseded duplicate UI declarations are no longer shipped.

Switching and recovery:
- One duplicate full diagnostic (about 6 s) before the vendor rebuild is removed. Every write still runs its own proof.
- The hnat runtime read is cached for 60 s, so it no longer runs dmesg twice and floods the kernel log on every diagnostic.
- Normal rollback waits for a restarted monitor to settle.
- Probe sockets use the whole probe budget, so a slow TCP tunnel is not a failure.
- procd respawns the services without a retry limit, and they reload only on the app's own configuration.

CI source `a050341e2a6aad7240d333caf299ec6e27e3aeb8`: pinned Python 3.11 and 3.9 runtimes, all suites PASS. The isolated Python 3.9 build is identical.
