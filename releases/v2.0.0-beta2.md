# HomenS.AI Auto VPN 2.0.0-beta2 (Lua line, stable candidate)

**Runtime:** as 2.0.0-beta1 (Lua monitor and Auto as two services by default, the C JSON module inside Lua, Python 3.9 as the base and fallback).

Owner findings from the physical power-cut test (01.11.2026):
- **The traffic light is never better than the monitoring lamp.** When the page cannot read the monitor (router off or restarting), the light is red ("No connection to the router program"), not green. Data that is only late is yellow, not green.
- **Recovery after a restart is shown as such.** While the boot resume is bringing back the Auto the owner had on, the page shows a yellow "Restoring after a router restart" (`AUTO-RESUME-PENDING`), instead of a red "Recovery needed / Auto does not work" or "Turning Auto off". The live status now carries `boot_resume` (Lua and Python monitors).

Fixes from the external tool sweep of beta1 (`docs/qa/EXTERNAL-TOOLS-2026-11-01.md`):
- **Python history reader:** a damaged `native-history.json` nested so deep that the JSON reader raised `RecursionError` now falls back to the backup file like other damage (found by hypothesis).
- **Page:** the history merge never writes through `__proto__`, `constructor` or `prototype` path parts (semgrep). The data only ever comes from the router's own RPC; this is hardening.
- **Repository:** shipped router files are LF in every checkout (`.gitattributes`), so a package built from a Windows checkout is the same as one built from `git archive`.
- **Test:** the `\u` escape case of `test_canon_keys.lua` really feeds an escape now.

Still open: F2 (`decode_keys` does not validate the fields it skips; the same in Lua and C) and F5 (a zero-length `memcpy` in `canon_c.c`, harmless in practice, needs a module rebuild).
