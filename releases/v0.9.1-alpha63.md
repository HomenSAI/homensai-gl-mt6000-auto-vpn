# Auto VPN 0.9.1-alpha63

Alpha63 contains all alpha60–alpha62 switching fixes. On the dedicated MT3000, alpha62 entered the vendor-rebuild recovery and restored and committed the original route_policy order. It then refused at the next pre-write check. The supervisor starts together with the monitor after an upgrade; the monitor renews every vendor generation, and the pair stays unsettled for ~30 s. Both bounded attempts were spent inside that window.

The rebuild now reads its diagnostics through a bounded settle wait: up to 90 s, polling every 3 s, while the diagnostics report only blockers or no selection. Nothing is written while it waits, and the decision is still made on the last reading. The final post-rebuild attestation uses the same bounded read. A pair that never settles still refuses before any further write.

CI source `cc8e8046454b5d2febc4f0303d86f9ecc7b392c0`: pinned Python 3.11 and 3.9, 1248/1248 application tests each. The isolated Python 3.9 build is identical.

Package: `homensai-auto-vpn_0.9.1-alpha63-1_all.ipk`, 984203 bytes, SHA256 `d5b18c39822e2522c39bf5862955136ec5a368dcd3e15dc31249a8d981b1b433`. Stable Latest remains v0.9.0.
