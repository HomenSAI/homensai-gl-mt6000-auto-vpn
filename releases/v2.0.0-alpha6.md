# HomenS.AI Auto VPN 2.0.0-alpha6 (Lua line, test build)

**Runtime:** this is the separate Lua line (branch `feat/lua-core-20261030`); the Python line 1.0.0-betaN stays the fallback. By default everything still runs on Python 3.9, exactly as 1.0.0-beta13. Two switches move parts to Lua 5.1:

| Part | Default | `option lua_auto '1'` | `option lua_core '1'` |
|---|---|---|---|
| Auto supervisor (pair loop, transaction, rollback and recovery, manual pair button, history writes) | Python | **Lua** (`lua/auto.lua daemon` under procd) | Python |
| Write stage of the instant manual switch | Python | **Lua** | **Lua** |
| Live probe of a profile before a switch/return (DNS + 2 HTTPS) | Python | Python, through the read-only bridge `lua_bridge.py` | Python |
| Monitoring, speed test, Telegram, the page (rpcd) | Python | Python | Python |

- **status.json: only the fields the supervisor reads.** `canon.decode_keys` builds `time`, `error`, `profiles`, `samples`, `vendor_observation`, `uplink_observation`, `observation_valid_for` (the same keys the Python supervisor reads) and skips the statistics structurally. On the live MT3000 file (230 KB): identical values, 360 → 170 ms per parse; with the single parse per version, ~720 → 170 ms per monitor write.
- **Less CPU at idle:** the monitor's `status.json` (205 KB, rewritten every 10.5 s) is decoded once per version for every reader of the supervisor (it was decoded twice; the exact pure-Lua decoder takes 380 ms per parse on the MT3000).
- **Diagnostics profiler:** `touch /var/run/homensai-vpn/lua-profile.request` profiles the Lua supervisor for 60 s into `lua-profile.json` (RAM); off by default.
- **Measured with alpha4:** `kill -9` of the Lua supervisor during APPLYING — restarted after 5 s, journal rolled back 9.5 s after the kill, pair cleanup finished, LAN guard removed (Auto off afterwards by design, as in Python).
- **Measured on the MT3000 with alpha3** (Lua Auto, the same router and channels as the Python baseline 1.0.0-beta13): idle Auto 22.5 % of one core and 12.1 MB (Python 55.7 % and 40.6 MB); 6 of 6 instant manual switches, traffic on the new channel after 2.6 s (1.9–3.6) and the button done after 4.0 s (Python 4.1 s / 5.5 s); 2 of 2 controlled faults switched to the reserve (COMMITTED 65–97 s after the fault) and returned to the primary (211–216 s).
- **Fix after the third router run (alpha3):** a kill during APPLYING was recovered correctly (journal rolled back in 7.4 s, Auto switched off by design as in Python), but the pair cleanup then failed with `PAIR-NETWORK-WRITE-FAILED`: the in-process copy of the packaged network write did not get its job on stdin. It now reads its own stdin; the router self-test runs the real network read and write in-process on a copy of the network config.
- **Fixes after the second router run (alpha2):** the Lua supervisor reached OBSERVING like Python, then crash-looped: nixio takes file modes only as strings, `nixio.open` does not take `'wx'`, and the MT3000 has no `stat(1)`. Modes are now octal strings, exclusive create uses `nixio.open_flags`, and the exact mode check reads nixio's `modestr` cross-checked with `modedec`.
- **Router self-test of the system layer** (`router_sys_selftest.lua`): every `sys` call against the router's own nixio/libubus/libuci from a `/tmp` copy, run before Lua is enabled.
- **Safety net `LUA-AUTO-FALLBACK`:** after 3 Lua errors within 10 minutes the process releases its lock and replaces itself with the Python supervisor (system log, error table, `RUNTIME/lua-auto-fallback.json`).
- **Fix after the first router run of alpha1:** with `lua_auto=1` the Lua supervisor stopped with `sys: unsafe command argument` when it armed the LAN guard release at Auto start (the release job holds the quoted nft element `'{ "br-lan" }'`, which the command quoting refused). procd restarted it and it recovered to STOPPED, so Auto did not start; nothing was switched and no guard was left. The job is now handed to `sh -c` with its own quotes escaped; a new test drives the real `sys.lua`.
- **Lua Auto supervisor (Lua plan item 1).** `backend.lua` ports `native_switch.Linux`, `recovery.lua` ports the rollback recovery, `auto.lua` runs under procd when `lua_auto` is on. The same files, journal phases, control revision, lock and refusal codes as Python; both supervisors take `native.lock`, so they never run together. Every input is cached by a cheap key (file inode/size/time, command text), so an idle pass costs milliseconds instead of re-running the helpers.
- **Known gaps with `lua_auto=1`** (listed in `docs/architecture/LUA-AUTO-ITEM1-2026-10-31.ru.md`): the speed test refuses `SPEED-PAUSE-UNVERIFIED`; the old non-pair manual queue is not served; switch events in the history have no latency/website captures.
- **Router check before this build** (MT3000, read-only, Python Auto running): the Lua backend reads the same uci, kernel rules, plan, kernel proof and journal and gives the same answers as Python; diagnostic with cache 115 ms against 750–850 ms in Python, 7.1 MB.
- Measurements of the supervisor on the router (idle CPU, memory, recovery after kill, Stop during a switch, automatic faults) are recorded in `docs/architecture/LUA-PLAN-2026-10-30.ru.md`, row 1.
