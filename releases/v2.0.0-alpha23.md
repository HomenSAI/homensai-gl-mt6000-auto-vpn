# HomenS.AI Auto VPN 2.0.0-alpha23 (Lua line, test build)

**Runtime:** as 2.0.0-alpha22 (two Lua processes by default, C JSON module on).

- **Faster checks while the firmware rebuilds a tunnel (owner decision 01.11, variant A):** the monitor runs a pass every 10 s while one of these holds:
  - a tunnel of the Auto pair is still settling after a firmware rebuild;
  - Auto is starting;
  - Auto is blocked only while waiting for the firmware.

  This lasts at most 600 s per wait. At probe level 1 the second matching observation used to come a whole minute later. The safety rules of the vendor gate are unchanged: two equal observations and the full settle period. The same rule is in the Python and Lua monitors, with the same tests. Analysis: `docs/architecture/VENDOR-SETTLING-2026-11-01.ru.md`.

## Tested on the GL-MT3000 (01.11.2026)

- Normal install over alpha22. The same firmware-rebuild faults as in the 3 h soaks were run (kill Auto, kill monitor, server unreachable, kill Auto mid-switch). All seven cycles returned to the primary. The block after a firmware rebuild is still 119–139 s: the 120 s settle period, counted from the first observed change, dominates. Variant A is harmless, and only variant B shortens the block (`docs/architecture/VENDOR-SETTLING-2026-11-01.ru.md`).
- Fast detection (`option lua_fast_detect '1'`, owner decision, enabled on this router): suspicion after 2.6–3.1 s and the Auto decision 26–28 s after the fault (58–88 s from cold without it). The traffic moved 1.3–1.6 s after the decision (`docs/architecture/SWITCH-SPEED-2026-11-01.ru.md`).
