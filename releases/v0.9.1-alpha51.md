# Auto VPN 0.9.1-alpha51

Tasks 1–3 of the [28 October work order](../docs/handoff/SOL-6.1-WORK-ORDER-2026-10-28.md).

Publication now verifies that the package-record commit is the direct child of the tested code commit, changes exactly the five allowed files and contains the exact CI package/hash/size. It uses the successful dual-runtime CI receipt for final code commit `4c0ecda151106eab0c7be1569276dcd28ddb6637`; no second CI run is required for its strictly verified record child. An earlier development candidate was also tested; independent review tightened the record check before the final code CI.

CI now runs tools and offline lab tests, records actual Lua-backed tests and refuses publication without Lua on the full tools runtime. A pinned offline Dockerfile reproduces the Python 3.11/Lua tools composition; the previous input images remain unchanged. The Gitea save timeout is 30 minutes. Every dashboard text replacement asserts its exact expected count. Four conversion stages preserved generated JS/CSS bytes, ignoring line endings; new release identity and the two publication-code descriptions are intentional additions. Historical packages and page modules stay in Git.

Final code CI: 889 application and 147 QA tests per runtime, 20 tools tests on Python 3.11 (explicitly skipped on Python 3.9 without Git), 60 offline lab cases per runtime, 13 executed Lua cases per runtime, 69 UI suites and two Node lab suites on Python 3.11. Python 3.11 has 2 QA skips; Python 3.9 has 37 complementary QA skips. Both runtimes and an independent Python 3.9 build produced the same package.

Package: `homensai-auto-vpn_0.9.1-alpha51-1_all.ipk`, 902881 bytes; SHA256 `e87946336bcf39981cda27132c14f44a3dfb848eeccc4901fd62fbfee5786e8b`.

Device delivery is gated separately: encrypted before/after backups, a normal Stop/install/verify/Start sequence and fresh router evidence are required before publication. This code batch changes no VPN algorithm. External LAN, 24-hour soak, power cut, IPv6 and MT6000 continuous-mode acceptance remain unproven. Loss of stock VPN rule bindings is not automatically repaired by this release.

Задачи 1–3 [наряда от 28 октября](../docs/handoff/SOL-6.1-WORK-ORDER-2026-10-28.md).

Перед публикацией программа строго проверяет, что коммит записи пакета — прямой потомок проверенного исходника, меняет только пять разрешённых файлов и содержит тот же пакет, хеш и размер. Используется успешная квитанция двух сред для окончательного исходника `4c0ecda151106eab0c7be1569276dcd28ddb6637`; второй прогон CI на точном коммите записи не нужен. Более ранний кандидат тоже проверялся; независимый разбор потребовал ужесточить проверку записи до окончательного CI.

В CI добавлены инструменты и автономные тесты стенда, квитанция считает реально выполненные проверки Lua; без них публикация запрещена. Добавлен закреплённый Dockerfile Python 3.11 с Lua для сборки без сети; прежние исходные образы сохранены. Сохранение в Gitea ждёт до 30 минут. Каждая текстовая замена при сборке страницы проверяет число совпадений. После каждой из четырёх групп изменений JS/CSS оставались прежними с учётом переводов строк; отдельно добавлены новая версия и описания двух кодов отказа публикации. Старые пакеты и страницы сохранены в Git.

Окончательный CI: 889 тестов приложения и 147 тестов QA в каждой среде; 20 проверок инструментов в Python 3.11 (в Python 3.9 явно пропущены из-за отсутствия Git); 60 автономных проверок стенда и 13 выполненных тестов Lua в каждой среде; 69 наборов UI и два набора Node для стенда в Python 3.11. Явные пропуски QA: 2 в Python 3.11 и 37 в Python 3.9. Обе среды и отдельная сборка Python 3.9 дали одинаковый пакет.

Пакет: `homensai-auto-vpn_0.9.1-alpha51-1_all.ipk`, 902881 байт; SHA256 `e87946336bcf39981cda27132c14f44a3dfb848eeccc4901fd62fbfee5786e8b`.

Установка проверяется отдельно: до публикации обязательны зашифрованные копии до/после, обычная процедура Стоп → установка → проверка → Старт и свежие доказательства с роутера. Этот пакет не меняет алгоритмы VPN. Внешний LAN, суточная работа, отключение питания, IPv6 и непрерывный режим MT6000 остаются непроверенными. Автоматического восстановления потерянных привязок штатных VPN-правил в этом выпуске нет.
