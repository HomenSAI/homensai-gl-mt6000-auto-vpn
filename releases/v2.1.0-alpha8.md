# HomenS.AI Auto VPN 2.1.0-alpha8 (Lua line, approved page, failure detector and fixes from the router tests)

**Runtime:** as 2.1.0-alpha7 (Lua by default, Python as the fallback; the same logic and shared test cases).

**Changes since 2.1.0-alpha7:**
- **The approved page.** The page is now the approved mockups: «Простой» / Simple (home and settings with an expert part), «Пульт» / Console (Channels, Auto, Servers, Journal, System) and a first-run wizard (Router → Channels → Behaviour → Terms and start). The view is switched by two icons next to the language button. Same calls and the same safety as before: saving never starts Auto, the terms are accepted only by the owner's own press. The main module is smaller (about 512 KB instead of 941 KB).
- **Channel-failure detector (HMM).** A 6-state model of the channel decides when to leave the primary (`failure_model hmm`, the default; `hmm-fast` and the previous rule `consecutive` stay selectable in the expert settings). A planned return from a healthy reserve also needs P(primary healthy) ≥ 0.90 or 300 s of healthy checks; a return from a reserve that failed itself is not gated.
- **A failover the GL vendor worker aborted is retried in seconds.** On the MT3000 (63-cycle soak, cycle 28) the vendor aborted a failover before any switch, the attempt was still charged and the next one waited 60 s: traffic moved after 84.2 s instead of 20–35 s. Now such an abort is refunded and retried after 5, 10, 20, 40 s; vendor gates are unchanged.
- **Faster return when the reserve fails itself** (`rescue_stable`, default 10 s, 0–60): the primary is proven with a short stability window instead of the full one. Tuning from the offline study: `primary_stable` 120 s by default, two lost heartbeats instead of three.
- **Large-packet check fixed.** On the MT3000 a firewall drop of large packets made the kernel refuse the large echoes, the check counted that as "unavailable" and `VPN-MTU` never appeared. Refused sends now count as lost echoes, and the status keeps the last reading in every pass (`mtu_check`).
- **Forward resume after a real restart.** On the MT3000 a killed switch still cost 129.8 s: the resume refused `CLIENT-STOP` after every real restart. Fixed; a refused resume keeps the pair clients.
- **Probe authenticity.** The three probe hosts are verified against their own pinned roots, every check carries a request nonce, and the status shows why a check is not trusted (`probe_trust`: untrusted certificate, portal redirect, stale response). Optional DNS check over DoH (`probe_dns doh`, default `udp`).
- **Optional Bayesian server pick** inside a channel (`server_pick_model bayes`, default `simple`).
- **After the owner's Stop** GL manages the tunnels again: the tunnel autostart and the stock `vpn-client` start link come back (only what the app itself changed).
- **Formal-model fixes** (K1 tail, K2–K5, K9, K11): guard after a power cut on the reserve, guard re-armed during a slow pair start, return hold after a restart, the COMMITTED write under the control lock, the guard kept while a session is held by a GL change, and the owner's Start no longer overwritten by a parallel cleanup. The formal model runs as an offline CI gate.
- **Honest P95.** Reports and the test history mark a P95 from fewer than 59 samples as an estimate. The test history now has the 2.1.0-alpha7 router results, including the first honest P95: primary drop, n = 61 — detection median 7.0 s, P95 7.47 s, max 9.64 s; traffic moved median 21.4 s, P95 29.8 s, max 84.2 s (cycle 28, fixed above).

**Что изменилось по сравнению с 2.1.0-alpha7:**
- **Утверждённая страница.** Страница теперь сделана точно по утверждённым макетам: «Простой» (главная и настройки с разделом для эксперта), «Пульт» (Каналы, Auto, Серверы, Журнал, Система) и мастер первого запуска (Роутер → Каналы → Поведение → Условия и запуск). Вид переключается двумя значками рядом с кнопкой языка. Вызовы и защита прежние: сохранение не запускает Auto, условия принимает только сам владелец. Основной модуль меньше (около 512 КБ вместо 941 КБ).
- **Детектор сбоя канала (HMM).** Модель канала на 6 состояний решает, когда уходить с основного (`failure_model hmm`, по умолчанию; `hmm-fast` и прежнее правило `consecutive` выбираются в настройках эксперта). Плановый возврат со здорового резерва требует ещё P(основной здоров) ≥ 0,90 или 300 с удачных проверок; возврат с отказавшего резерва не задерживается.
- **Переключение, отменённое воркером GL, повторяется через секунды.** На MT3000 (63 цикла, цикл 28) вендор отменил уход на резерв до переключения, попытка всё равно засчиталась, и следующая ждала 60 с: трафик перешёл через 84,2 с вместо 20–35 с. Теперь такая отмена не засчитывается, повтор через 5, 10, 20, 40 с; проверки вендора не изменились.
- **Быстрый возврат, когда отказал сам резерв** (`rescue_stable`, по умолчанию 10 с, 0–60): основной подтверждается коротким окном стабильности вместо полного. Настройка по офлайн-исследованию: `primary_stable` 120 с по умолчанию, два потерянных пульса вместо трёх.
- **Исправлена проверка больших пакетов.** На MT3000 сброс больших пакетов файрволом заставлял ядро отказывать в отправке, проверка считала это «недоступно», и `VPN-MTU` не появлялся. Отказанная отправка теперь считается потерянным эхо, а статус держит последнее показание в каждом проходе (`mtu_check`).
- **Доведение переключения после настоящего перезапуска.** На MT3000 убитое переключение всё ещё стоило 129,8 с: доведение отказывало с `CLIENT-STOP` после каждого настоящего перезапуска. Исправлено; при отказе клиенты пары сохраняются.
- **Подлинность проверок.** Три хоста проверки сверяются со своими закреплёнными корневыми сертификатами, каждая проверка несёт одноразовую метку, статус показывает, почему проверке нельзя верить (`probe_trust`: сертификат, перенаправление портала, устаревший ответ). Необязательная проверка DNS через DoH (`probe_dns doh`, по умолчанию `udp`).
- **Необязательный байесовский выбор сервера** внутри канала (`server_pick_model bayes`, по умолчанию `simple`).
- **После твоего Stop** туннелями снова управляет GL: автозапуск туннелей и стандартная ссылка запуска `vpn-client` возвращаются (только то, что меняло само приложение).
- **Исправления по формальной модели** (хвост К1, К2–К5, К9, К11): защита после отключения питания на резерве, защита взводится заново при медленном запуске пары, удержание возврата после перезапуска, запись COMMITTED под замком управления, защита сохраняется, пока сессия удержана правкой в GL, Start владельца больше не перезаписывается параллельной очисткой. Формальная модель стала проверкой офлайн-CI.
- **Честный P95.** Отчёты и история тестов помечают P95 из менее чем 59 замеров как оценку. В истории тестов теперь есть результаты 2.1.0-alpha7 на роутере, включая первый честный P95: отказ основного, n = 61 — обнаружение медиана 7,0 с, P95 7,47 с, max 9,64 с; трафик перешёл медиана 21,4 с, P95 29,8 с, max 84,2 с (цикл 28, исправлено выше).

Verified on the router (MT3000, on 2.1.0-alpha7): the defects fixed above (vendor abort in cycle 28, the missed large-packet check, the refused forward resume) and the primary recheck (a 15 s outage stayed on the primary in 3 of 3). Not yet verified on the router: every change of 2.1.0-alpha8 itself — it passes unit, shared-case, mutation, simulator and formal-model tests in both runtimes. / Проверено на роутере (MT3000, на 2.1.0-alpha7): исправленные выше ошибки (отмена вендором в цикле 28, пропущенная проверка больших пакетов, отказ доведения переключения) и повторная проверка основного (обрыв 15 с остался на основном в 3 из 3). Ещё не проверено на роутере: сами изменения 2.1.0-alpha8 — они проходят модульные тесты, общие случаи, мутации, симулятор и формальную модель в обоих вариантах.
