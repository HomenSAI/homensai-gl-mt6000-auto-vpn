- **Power cut, found by the fault-matrix trial on alpha11 (sysrq-b at idle on the MT3000):** after the cut the Auto intent (RAM) and the stock boot prefix (tmpfs) were gone. Every rollback of the held journal refused `RTP-BOOT-PRECONDITION-UNVERIFIED` until `ROLLBACK-GIVEN-UP`, and Start then refused `TRANSACTION-IN-PROGRESS`; the LAN stayed without internet until a reinstall. Recovery now recreates exactly the prefix stock boot creates (two empty directories, the zero-byte gate) before it rolls back, in Lua and in Python.
- **Auto comes back after a power cut (owner decision 31.10.2026):** the owner's own Start leaves a durable marker on flash; after a boot the monitor presses Start once for the owner with every Start check (retried every 15 s for up to 10 min). A later Stop or an automatic give-up cancels it; test and programmatic starts never leave the marker. Reasons are the `AUTO-RESUME-*` family on the page.
- **Power-cut integrity (`docs/architecture/POWER-CUT-INTEGRITY-2026-10-31.ru.md`):** one durable write for flash files (temp file, fsync, rename, fsync of the directory); a damaged state file is the coded refusal `STATE-FILE-DAMAGED` with a quarantine copy instead of a restart loop; a cut between the UCI order and the kernel rebuild no longer leaves traffic on the reserve while the journal says primary; recovery waits up to 60 s for a tunnel device before the VPN-only guard and never blocks the LAN while waiting; leftover `.pending` files are removed at start.
- **Live probe in Lua (plan item 4):** the supervisor's probe no longer starts Python (~2 s of CPU each): three HTTPS checks through `curl --interface` together and a device-bound DNS query; the same fields and codes as Python (40 differential scenarios). An instant manual click skips the boot-prefix lock when the prefix is already in place.
- **Fast outage detection (plan item 5, off by default):** one ICMP echo per second through each pair channel on a persistent socket, no process per beat; 3 lost beats start the existing dense confirmation episode; Auto keeps its own switch rules. Simulated: switch rule met 22–28 s after a 150 s outage (48–148 s without); blips of 4–12 s do not switch.
- **Speed test with the Lua supervisor (plan item 7):** the pause handshake now knows the Lua services, so the speed test no longer refuses `SPEED-PAUSE-UNVERIFIED` under `lua_auto`; speed test and Telegram reports run in Lua with the same files and texts as Python. No real Telegram message was sent in testing.
- **Buttons and channel path in Lua:** Start, Stop and the fault-test cancel write the same request files as Python; the channel path uses the supervisor's own confirmed kernel check (at most 15 s old) instead of running `iptables-save` from the bridge.

2.0.0-alpha12 — отдельная линия Lua, тестовая сборка.

Пробный прогон матрицы сбоев на alpha11 нашёл тупик после отключения питания: команда «Auto включён» и служебная заготовка прошивки хранятся в оперативной памяти, после перезагрузки откат журнала не мог пройти, Start отказывал, у LAN не было интернета до переустановки. Теперь восстановление само создаёт эту заготовку (два пустых каталога и пустой файл-метку) перед откатом — в Lua и в Python. По решению владельца Auto, включённый владельцем, после отключения питания включается сам (все проверки Start выполняются; Stop это отменяет).

Также: надёжная запись на флеш и коды вместо перезапусков по кругу при повреждённых файлах; живая проверка канала в Lua без запуска Python; быстрое обнаружение сбоя (пульс 1 с, по умолчанию выключено); тест скорости и Telegram на Lua (тест скорости работает при Lua Auto); кнопки Start/Stop/отмена теста сбоя и путь канала на Lua.

**Ядро:** по умолчанию всё на Python 3.9. С `lua_auto=1` супервизор Auto и живая проверка канала — на Lua; с `lua_monitor=1` монитор, чтение страницы, кнопки, путь канала, тест скорости и Telegram — на Lua. На Python остаются: запуск самого теста сбоя, панель ручного переключения и состояние сканирования для страницы (мост), запасной путь для всех кнопок.
