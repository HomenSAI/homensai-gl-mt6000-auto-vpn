# Auto VPN 0.9.1-alpha41

Auto now starts an operator-enabled but stopped VPN client itself (bounded: one attempt per two minutes, four per 15 minutes, Stop-fenced), so a reserve no longer stays "Connecting..." and blocks the pair. A stopped reserve is reported as the new code RESERVE-NOT-CONNECTED. Auto ignores two kinds of stock-firmware housekeeping that it used to read as an external change: the exit bookkeeping options the GL client adds to a firewall zone, and stopped leftover client sections removed from network and dhcp. Channels now show "Reliability problem: check loss N% (X of Y checks in 5 min)" with the catalogue code CHANNEL-UNRELIABLE when the router's own checks fail in at least 20% of cycles; the Tests page recommends which channel to keep and names the best measured alternative. This is the measured share of failed checks, not an ICMP packet-loss figure, and changes no setting or route. The Help page also carries the Auto operation diagram from alpha36.

Immutable CI passed in Python 3.11 and 3.9, and two isolated package builds equal the CI hash. The dedicated GL-MT3000 runs this package with Auto ON: the primary channel lost 56-70% of test packets, Auto switched to the working reserve and the pair stayed healthy. Earlier installs of this series on the same router exposed the firmware side effects above; they are fixed here. Not proven: native browser rendering of the new labels, external LAN confirmation, 24-hour soak, power-cut, IPv6 and a return to a recovered primary. Stable main/latest semantics are unchanged.

---

Auto сам запускает включённый, но остановленный VPN-клиент (не чаще раза в две минуты и четырёх раз за 15 минут, с защитой от Stop), поэтому резерв больше не висит в «Connecting...» и не блокирует пару. Остановленный резерв показывается новым кодом RESERVE-NOT-CONNECTED. Auto больше не принимает за внешнее изменение штатные действия прошивки: служебные опции файрвола и удаление остановленных клиентов из network и dhcp. Каналы показывают «Проблема с надёжностью: потери проверок N% (X из Y за 5 мин)» с кодом CHANNEL-UNRELIABLE, если проверки роутера не проходят в 20% циклов и более; страница «Тесты» рекомендует, какой канал держать, и называет лучший измеренный кандидат. Это доля непройденных проверок, не ICMP-потеря пакетов; настройки и маршруты не меняются.

CI прошёл в Python 3.11 и 3.9, два независимых билда совпали с хэшем CI. На выделенном GL-MT3000 пакет работает с включённым Auto: основной канал терял 56–70% тестовых пакетов, Auto переключился на рабочий резерв. Не проверено: отрисовка новых подписей в браузере, внешний LAN, суточный тест, отключение питания, IPv6 и возврат на восстановившийся основной.
