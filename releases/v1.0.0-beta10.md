# HomenS.AI Auto VPN 1.0.0-beta10

1.0.0-beta10 answers the page buttons from the running service and removes repeated work found by profiling on the router. A manual switch now completes in about 5 s.

- **Buttons through the running service.** These buttons are answered by the monitor that is already running, through its local socket, so Python no longer starts for every click:
  - Start/Stop Auto;
  - the failure test;
  - the probe level;
  - the response method.

  If the service is unavailable, the old path is used. Once a button has acted, its result is never repeated: an unconfirmed result is shown as RPC-UNCONFIRMED.
- **Light check of a manual click.** The click is gated from RAM state only. In beta9 the full button model took 2.5–6 s under load. The Auto service still proves everything before it switches.
- **Two costs removed** (profiled on the MT3000):
  - checking every number while reading state files took 0.42 s of a 1.37 s diagnostic;
  - parsing the same kernel rules again took 0.55 s of a 0.77 s kernel proof.

  The validation rules are unchanged: non-finite numbers, oversized integers and duplicate fields are still refused.
- **Memory safeguard.** The resident history copy is kept only while at least 64 MB of RAM is available.
- **Measured on the MT3000** (30 Oct 2026, Auto on):

  | Button | 1.0.0-beta9 | 1.0.0-beta10 |
  |---|---|---|
  | Start Auto (answer) | 1.06 s | 0.30 s |
  | Cancel failure test | 1.04 s | 0.21 s |
  | Manual click (answer) | 0.9–3.1 s | 0.5–0.8 s |

  Manual switch, 3 to the reserve and 3 back:

  | From the click to | beta7 | beta8 | beta9 | **beta10** |
  |---|---|---|---|---|
  | Traffic on the new channel | ~25 s | 10.8 s | 8.2 s | **4.2 s (3.2–5.3)** |
  | Button finished | 42 s | 16.6 s | 9.9 s | **5.4 s (4.2–6.6)** |

  Mean stages in beta10:

  | Stage | Time |
  |---|---|
  | Request | 0.6 s |
  | Waiting for the supervisor | 0.9 s |
  | Checks before (diagnostic 0.9 s, kernel proof 0.5 s) | 1.5 s |
  | Route change (rule order 1.0 s, atomic kernel switch 0.2 s) | 1.1 s |
  | Checks after | 0.3 s |
  | Saving and display | 0.9 s |

- **Memory** (beta10, 6 minutes after start, 480 MB RAM in total):

  | Service | Memory | Share of RAM |
  |---|---|---|
  | Monitor service | 48 MB | ~10% |
  | Auto service | 41 MB | ~9% |

  - About 7 MB of each figure is the Python program and libraries mapped from flash. That part is physically shared, so it is counted twice in the sum.
  - The rest is each service's working data. It includes the copies kept in memory: the history (about 8 MB) and the page status (about 3 MB). Python also keeps freed memory for reuse, so the figure stays near its peak.

1.0.0-beta10 — кнопки через работающую службу, ручное переключение примерно за 5 секунд.

**Кнопки через работающую службу.** Эти кнопки отвечают за 0,2–0,3 с вместо ~1 с:
- старт и стоп Auto;
- тест сбоя;
- уровень опроса;
- способ отклика.

**Ручное переключение:**

| От нажатия до | beta9 | beta10 |
|---|---|---|
| Трафик на новом канале | 8,2 с | **4,2 с (3,2–5,3)** |
| Кнопка завершила | 9,9 с | **5,4 с (4,2–6,6)** |

**Найдено профилированием на роутере и убрано:**
- лишняя проверка чисел при чтении файлов;
- повторный разбор одних и тех же правил ядра.

**Память.** Служба мониторинга занимает 48 МБ, служба Auto — 41 МБ. Около 7 МБ в каждой цифре — это сам Python и библиотеки: они общие для обеих служб, поэтому в сумме посчитаны дважды. Остальное — рабочие данные каждой службы, вместе с копиями в памяти: история около 8 МБ и статус около 3 МБ. История держится в памяти, только пока свободно не меньше 64 МБ.
