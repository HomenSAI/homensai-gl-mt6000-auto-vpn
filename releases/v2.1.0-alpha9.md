# HomenS.AI Auto VPN 2.1.0-alpha9 (Lua line: network journal and slider advisor, GL-based sensors, signed releases, fixes from two independent reviews)

**Pre-release, test build.** Same runtime as 2.1.0-alpha8 (Lua by default, Python as the fallback; the same logic and shared test cases).

## Changes since 2.1.0-alpha8

### In plain words

- **The program now learns how your network behaves.** The monitor keeps a small diary of the last 30 days (about 3 KB a day, in memory, saved to flash once a day). At 03:30, at the lowest priority, an advisor replays your past outages against the real decision code and suggests where the main slider "Fast reaction <-> No needless switches" should stand. By default it only **advises**; you press the button. "Auto" (moves the slider by itself, at most one step a day, never during an outage) and "Manual" can be chosen. "Auto" becomes the default for ordinary users only after a 7-day check on the router.
- **A new main slider with a chart, a table, fine tuning and a 5-step training**, and a new simple-view card "Auto-adaptation". The page style is the F1 style "Golden grid" for the Simple view, the Console and the first-run wizard. Slider ticks follow the page language.
- **Honest numbers.** Recovery time is shown as a named P95 only when there are at least 59 samples; with fewer samples the page says "approximately" and states how much the maximum can honestly claim.
- **Smarter about "no internet at all".** The router now tells apart "the uplink is down" from "a VPN tunnel is down". While the uplink is proven down Auto does not switch (it would only add noise); after the uplink returns it waits one check. It also listens to WireGuard events and notices a tunnel that sends but receives nothing.
- **A changed VPN server key is noticed.** The key of every VPN server is remembered on first sight (the same idea as SSH). By default the program only **warns**; "Accept new key" is a button.
- **The first-run wizard can always be left.** Every step has "Skip - open the interface". Skipping never starts Auto and never accepts the terms for you. On a router where Auto already runs or a pair is configured the wizard is no longer forced.
- **The footer names the program, not the package and the page build.**
- **Fewer wrong decisions in rare corners.** Fixes found by an independent review and by checking the code against the formal model: for example the autostart restore no longer undoes the preparation of a Start that follows a Stop, and a vendor rebuild of the reserve can no longer hold Auto on the reserve for ever (this one was found on the router during the 2.1.0-alpha8 tests, see below).
- **Releases can be signed.** A signed release chain, a second factor (phone code with one-time recovery codes), public timestamps and portable encrypted backups are in place; the whole set was rehearsed on test keys.
- **Documentation.** A plain-language refresh (how it works, where the idea comes from), and a new chapter on the scientific principles of the program (EN/RU).


- **Consistent indicators on every page.** One table defines the lamp, text and switch: confirmed enabled state survives waits and failures; a vendor wait is yellow and a proven failure is red. The carrying channel follows the verified route; bounded display memory never authorizes a route change.
- **Optional Russian Telegram brief.** Explicit `brief` groups errors, counts retained completed route changes, shows current five-minute reliability from the page sample population and always includes an alarm line. Existing defaults stay unchanged. It is not weekly or monthly uptime.
- **Additional logging and publication protection.** Sensitive-string masking covers tracebacks; signed assets are bound to reviewed Git objects and the release-record scope remains bounded.

### For administrators

All new options are UCI options of `homensai_vpn.main`. The defaults below are the shipped ones.

**Advisor and slider**
- Network journal `netjournal.json` (RAM, saved to flash once a day, 30 days); nightly advisor at 03:30, `nice 19`; modes `advice` (default), `auto`, `manual`; every change goes to the journal with a reason. New RPCs for the advisor and `server_key_accept`.
- Fast end of the slider (all **off** by default): the rule "HMM **or** N failed samples in a row" (switched on only by slider positions -0.1 / -0.2), `slider_fast` (administrator switch for the fast segment), `slider_turbo` (heartbeat rule; needs the owner's exact phrase; up to about 8 needless switches a day (unmeasured simulator estimate)). Event wake of Auto (`auto_event_wake`) is on. The recheck beside the preparation (`parallel_recheck`) defaults **off** until measured; a saved owner choice is preserved.
- Honest P95 of recovery time on the page; the few-data note shows the router reason once.

**Sensors (GL 4.11 based)**
- `wan_sensor` (on): own echo through the WAN port, the GL kmwan verdict, the repeater captive-portal flag, link state, both channel probes -> `WAN-DOWN` (no switching while the uplink is proven down) and `WAN-RECOVERING` (one check after return). Unknown evidence = the previous behaviour.
- `wg_events` (on): hotplug hook for WireGuard rekey events (suspicion only, never proof). `stall_sensor` / `stall_veto` (on): tx grows while rx stands for 3 s raises suspicion; rx flowing at 10 kbit/s or more vetoes a lost heartbeat. `heartbeat_quorum` (off): 3 targets from a pool of 8 with rotation, a beat counts as lost when 2 of 3 do not answer; it was not better in the simulator.
- `keep.d` for sysupgrade; a planned GL reboot and a kernel fault are told apart from a power cut; the diagnostic bundle masks public addresses, IPv6, chat ids, SSIDs and free-text secrets.

**Server key pinning** `server_key_pin` = `warn` by default (trust on first use); `enforce` acts on a changed key instead of only warning; RPC `server_key_accept` accepts the new key.

**Probe log by target** `probe_target_log` (on): one row per probe and target in RAM (tmpfs), never written to flash, not used for decisions; RPC `probe_targets`.

**Wave 3** - flap damping of the return: `recovery_flap_model` = `double` (default) with `recovery_flap_limit` 2 within `recovery_flap_window` 60 min (the old behaviour: limit 3 within 15 min; set `3` / `15`), alternative `halflife`; retry pauses after an aborted switch follow Fibonacci steps (`retry_backoff` = `fibonacci`, `fixed` = the previous 5 s); `probe_spread` (on); `reserve_probe_interval` (0 = off, or 20-120 s).

**CUSUM** `cusum_trigger` (off), soft RTT signal `rtt_watch` (off, code `CHANNEL-CONGESTED`), heartbeat RTT log `heartbeat_rtt_log` (on). They are off until data from the router exists.

**Fixes (both runtimes)**
- The Auto supervisor now receives the owner's `failure_model` and `server_pick_model` and the numeric detector options. Before this fix the supervisor always decided by the factory `hmm` (theta 0.8) while the monitor and the page showed the owner's values; earlier router tests of the slider and of `failure_model` therefore did not exercise the Auto decision.
- A vendor rebuild of the reserve (changed `vendor_generation`) no longer leaves Auto on the reserve with `RESERVE-IDENTITY-UNKNOWN`: the same tunnel with a quiet vendor and a healthy streak is the same reserve; otherwise Auto returns to a stably healthy primary by the planned rule. The same for a manual hold. (Found on the router, 04.11, 2.1.0-alpha8: Auto stayed on the reserve for over an hour with both tunnels healthy until Stop and Start.)
- An outside change held by the K9 rule (a GL edit) no longer rewrites the state on every pass, and an orphaned VPN-only guard is released after a refused Start or the owner's Stop.
- Autostart restore never undoes the preparation of a Start that follows the owner's Stop.
- Trace-conformance findings T1-T4 and model rules G1-G7, K12 (the list of known gaps is empty); the reload of the rollback without a dispatch belongs to the recovery only.
- Security: `/etc/config/homensai_vpn` is shipped and kept `0600`; an offline secret scanner runs in the pre-commit hook, in the publication path and in CI.

**Release tooling (not part of the router runtime)** - usign Ed25519 signatures of the package, the signed release chain `releases/CHAIN.jsonl`, OpenTimestamps proofs, TOTP with one-time recovery codes, portable `age` backups, a signing test lab and signed test-report manifests. `02-install.sh` verifies the signature and the chain before it changes anything (`--allow-unsigned` skips this for packages released before signing). The whole procedure was rehearsed on test keys.

**CI and formal model** - `scripts/offline-ci.ps1 -TraceCheck` also checks the code against the formal model (trace conformance); the TLA+ spec is cross-checked with TLC where Docker is available; the formal model has profiles for G1-G7 and K12.


**Fixes of the second independent review** (branch `fix/safety-review-a9-20261104`, 8 commits): a changed server key refuses a move onto its channel but no longer blocks Stop or every decision of a working pair; a refuted heartbeat run costs one lease instead of one per pass (about 8640 flash writes a day, turbo only) and keeps the owner's hold; a stuck queued click ends one pause only and expires; a pending owner click stops the advisor; flap damping counts failovers only (returns, repairs and manual switches are not counted); `keep.d` keeps `server-keys.json`, `netjournal.json`, `advisor-changes.json` and `keys.local/` across sysupgrade; `setup_save` accepts the flap fields.
**Expert settings page** (branch `feat/ui-expert-a9-20261104`, needs the previous item first): the fast end of the main slider (positions -0.1 / -0.2 behind the administrator switch; five turbo points locked until the owner types the phrase, with a plain warning) and the collapsed group "For expert -> Detector and sensors" with 19 fields (defaults and safe ranges shown; only changed fields are sent). New RPC `setup_detector`.

## Verified and not verified on a router

**Measured on the router (MT3000):** the 2.1.0-alpha8 primary-drop test (63 cycles, 58 counted) is recorded in the test history in this release: detection median 5.77 s (2.1.0-alpha7: 7.0 s), traffic moved median 20.68 s (21.38 s), back on the primary median 205.1 s (234.1 s); every counted cycle switched and settled back; n = 58 is below 59, so its P95 values (7.69 s / 26.65 s / 214.8 s) are **approximate**, not bounds. One more cycle is kept as a failed, excluded row: it ran during an outage of the upstream path and then inside the program fault above (fixed in this release).

## Что изменилось по сравнению с 2.1.0-alpha8

### Простыми словами

- **Программа учится на поведении вашей сети.** Монитор ведёт небольшой дневник за 30 дней (около 3 КБ в сутки, в памяти, раз в сутки сохраняется во флеш). В 03:30 с самым низким приоритетом советник «переигрывает» прошлые обрывы настоящим кодом решения и подсказывает, где поставить главный ползунок «Быстрая реакция <-> Без лишних переключений». По умолчанию он только **советует**; применяете вы сами кнопкой. Можно выбрать «Авто» (сам двигает ползунок не больше чем на шаг в сутки и никогда во время обрыва) и «Ручной». Для обычных пользователей «Авто» станет умолчанием только после 7-дневной проверки на роутере.
- **Новый главный ползунок** с графиком, таблицей, тонкой настройкой и обучением из 5 шагов, а на простой странице — карточка «Автоподстройка». Стиль страницы — стиль F1 «Золотая сетка» для «Простого», «Пульта» и мастера первого запуска. Метки ползунка следуют языку страницы.
- **Честные числа.** Время восстановления показывается как P95 с названием только при 59 и более замерах; при меньшем числе страница пишет «примерно» и говорит, что честно можно утверждать про максимум.
- **Умнее при «вообще нет интернета».** Роутер различает «лежит внешний канал» и «упал туннель VPN». Пока внешний канал доказанно лежит, Auto не переключается (это только добавило бы шума); после возврата ждёт одну проверку. Роутер также слушает события WireGuard и замечает туннель, который отправляет, но ничего не получает.
- **Смена ключа VPN-сервера не остаётся незамеченной.** Ключ каждого сервера запоминается при первой встрече (как в SSH). По умолчанию программа только **предупреждает**; «Принять новый ключ» — кнопка.
- **Из мастера первого запуска всегда можно выйти.** На каждом шаге есть «Пропустить — открыть интерфейс». Пропуск никогда не запускает Auto и не принимает условия за вас. Если на роутере уже работает Auto или настроена пара, мастер больше не навязывается.
- **В подвале страницы — название программы, а не пакет и сборка страницы.**
- **Меньше неверных решений в редких углах.** Исправления по независимому ревью и по сверке кода с формальной моделью: например, восстановление автозапуска больше не отменяет подготовку Start после Stop, а пересборка резерва вендором больше не может навсегда оставить Auto на резерве (эту ошибку нашли на роутере при тестах 2.1.0-alpha8, см. ниже).
- **Выпуски можно подписывать.** Есть подписанная цепочка выпусков, второй фактор (код с телефона и одноразовые коды восстановления), публичные отметки времени и переносимые зашифрованные бэкапы; весь набор отрепетирован на тестовых ключах.
- **Документация.** Обновлено простыми словами (как это работает, откуда идея) и добавлена глава о научных принципах программы (RU/EN).


- **Одинаковые светофоры на всех страницах.** Одна таблица задаёт лампу, текст и переключатель: подтверждённое включение сохраняется при ожидании и отказе; ожидание прошивки жёлтое, реальный отказ красный. Канал трафика показывается по проверенному маршруту; ограниченная память отображения не даёт права переключать маршрут.
- **Короткий русский Telegram-отчёт — по выбору.** Вариант `brief` группирует ошибки, показывает переключения из сохранённых событий, текущую надёжность за 5 минут из тех же проб, что страница, и обязательную строку аварии. Умолчание остальных пользователей не меняется. Это не uptime за неделю или месяц.
- **Дополнительная защита журналов и публикации.** Маскирование секретных строк распространяется на traceback; подписанные ассеты привязаны к проверенным Git-объектам, область записи выпуска остаётся ограниченной.

### Для администратора

Все новые опции — опции UCI `homensai_vpn.main`. Ниже указаны поставляемые значения по умолчанию.

**Советник и ползунок**
- Дневник сети `netjournal.json` (ОЗУ, раз в сутки во флеш, 30 дней); ночной советник в 03:30, `nice 19`; режимы `advice` (по умолчанию), `auto`, `manual`; каждое изменение пишется в журнал с причиной. Новые RPC советника и `server_key_accept`.
- Быстрый край ползунка (всё **выключено** по умолчанию): правило «HMM **или** N подряд проваленных проб» (включается только положениями ползунка -0,1 / -0,2), `slider_fast` (переключатель администратора для быстрого сегмента), `slider_turbo` (правило по пульсу; нужна точная фраза владельца; до ~8 лишних уходов в сутки (неизмеренная оценка симулятора)). Пробуждение Auto по событию (`auto_event_wake`) включено. Перепроверка рядом с подготовкой (`parallel_recheck`) по умолчанию **выключена** до замера; сохранённый выбор владельца не сбрасывается.
- Честный P95 времени восстановления на странице; заметка «мало данных» показывает причину роутера один раз.

**Датчики (по образцу GL 4.11)**
- `wan_sensor` (вкл.): собственное эхо через порт WAN, вердикт GL kmwan, признак captive portal у повторителя, линк, пробы обоих каналов -> `WAN-DOWN` (не переключать, пока внешний канал доказанно лежит) и `WAN-RECOVERING` (одна проверка после возврата). Нет доказательств — прежнее поведение.
- `wg_events` (вкл.): хук hotplug для событий пересогласования WireGuard (только подозрение, не доказательство). `stall_sensor` / `stall_veto` (вкл.): tx растёт, rx стоит 3 с — подозрение; rx течёт со скоростью от 10 кбит/с — вето на потерянный удар пульса. `heartbeat_quorum` (выкл.): 3 цели из пула 8 с ротацией, удар потерян, если не ответили 2 из 3; в симуляторе лучше не стало.
- `keep.d` для sysupgrade; плановая перезагрузка GL и сбой ядра отличаются от отключения питания; диагностический пакет маскирует публичные адреса, IPv6, идентификаторы чатов, имена Wi-Fi и секреты в свободном тексте.

**Закрепление ключей серверов** `server_key_pin` = `warn` по умолчанию (доверие при первой встрече); `enforce` действует при смене ключа, а не только предупреждает; RPC `server_key_accept` принимает новый ключ.

**Журнал проб по целям** `probe_target_log` (вкл.): строка на пробу и цель в ОЗУ (tmpfs), никогда не пишется во флеш, в решениях не участвует; RPC `probe_targets`.

**Волна 3** — сдерживание дребезга при возврате: `recovery_flap_model` = `double` (по умолчанию), `recovery_flap_limit` 2 за `recovery_flap_window` 60 мин (прежнее поведение: лимит 3 за 15 мин — задайте `3` / `15`), альтернатива `halflife`; паузы повторов после отменённого переключения идут по Фибоначчи (`retry_backoff` = `fibonacci`, `fixed` — прежние 5 с); `probe_spread` (вкл.); `reserve_probe_interval` (0 — выкл., или 20–120 с).

**CUSUM** `cusum_trigger` (выкл.), мягкий сигнал RTT `rtt_watch` (выкл., код `CHANNEL-CONGESTED`), журнал RTT пульса `heartbeat_rtt_log` (вкл.). Пока нет данных с роутера, выключены.

**Исправления (оба рантайма)**
- Супервизор Auto теперь получает `failure_model` и `server_pick_model` владельца и числовые параметры детектора. До этого исправления супервизор всегда решал по заводскому `hmm` (theta 0,8), тогда как монитор и страница показывали значения владельца; прежние тесты ползунка и `failure_model` на роутере поэтому не проверяли решение Auto.
- Пересборка резерва вендором (сменился `vendor_generation`) больше не оставляет Auto на резерве с `RESERVE-IDENTITY-UNKNOWN`: тот же туннель при спокойном вендоре и здоровой серии — тот же резерв; иначе Auto возвращается на стабильно здоровый основной по плановому правилу. То же для ручного удержания. (Найдено на роутере 04.11 на 2.1.0-alpha8: Auto больше часа оставался на резерве при здоровых обоих туннелях, пока не нажали Stop и Start.)
- Внешняя правка в GL, удержанная правилом К9, больше не переписывает состояние на каждом проходе, а осиротевшая защита VPN-only снимается после отказа Start или Stop владельца.
- Восстановление автозапуска никогда не отменяет подготовку Start, идущего после Stop владельца.
- Находки сверки кода с моделью T1–T4 и правила модели G1–G7, K12 (список известных пробелов пуст); перезагрузка отката без отправки принадлежит только восстановлению.
- Безопасность: `/etc/config/homensai_vpn` поставляется и сохраняется с правами `0600`; автономный сканер секретов работает в pre-commit, при публикации и в CI.

**Инструменты выпуска (не часть рантайма роутера)** — подписи пакета usign Ed25519, подписанная цепочка выпусков `releases/CHAIN.jsonl`, отметки OpenTimestamps, TOTP с одноразовыми кодами восстановления, переносимые бэкапы `age`, тестовая лаборатория подписи и подписанные манифесты отчётов о тестах. `02-install.sh` проверяет подпись и цепочку до любых изменений (`--allow-unsigned` пропускает проверку для пакетов, выпущенных до подписей). Вся процедура отрепетирована на тестовых ключах.

**CI и формальная модель** — `scripts/offline-ci.ps1 -TraceCheck` проверяет ещё и код против формальной модели (сверка трасс); спецификация TLA+ сверяется с TLC, где есть Docker; в формальной модели есть профили для G1–G7 и K12.


**Исправления второго независимого ревью** (ветка `fix/safety-review-a9-20261104`, 8 коммитов): смена ключа сервера запрещает переход на его канал, но больше не блокирует Stop и все решения работающей пары; опровергнутая серия потерянных ударов пульса стоит одну аренду вместо аренды на каждый проход (около 8640 записей во флеш в сутки, только turbo) и сохраняет удержание владельца; застрявший в очереди клик заканчивает только одну паузу и истекает; ожидающий клик владельца останавливает советник; сдерживание дребезга считает только уходы на резерв (возвраты, ремонты и ручные переключения не считаются); `keep.d` сохраняет `server-keys.json`, `netjournal.json`, `advisor-changes.json` и `keys.local/` при sysupgrade; `setup_save` принимает поля дребезга.
