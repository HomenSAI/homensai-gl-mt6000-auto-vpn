# HomenS.AI Auto VPN 2.1.0-alpha1 (Lua line, first server-pick build)

**Runtime:** as 2.0.0-beta5, plus the server pick below (Lua by default, Python as the fallback; the same logic and shared test cases).

**Changes since 2.0.0-beta5:** owner decision of 02.11.2026 (design: `docs/architecture/SERVER-PICK-DESIGN-2026-11-02.ru.md`):
- **Best server inside a channel.** **Off by default** until it is checked on the router.
  - Every GL tunnel has its own server list (`/etc/vpn_profiles.d/profile<tunnel>`). The router measures those servers from itself through the WAN, at most every 10 minutes and right after a channel failure: OpenVPN by the TCP connect time to the server port, WireGuard by ping.
  - The best working server is put right after the current one in the list, so the firmware's own server rotation takes it next.
  - A failed channel that carries no traffic gets the best server the way GL itself changes servers (uci and ifdown/ifup of that interface only). Auto must be on.
  - Limits: the channel that carries traffic is never touched; a working server is replaced only by one at least 20% faster; at most 4 changes per hour per channel; a running GL server switch is never interrupted.
  - New codes: `SERVER-PICKED`, `SERVER-PICK-FAILED`, `SERVER-PICK-WAITING-VENDOR`, `SERVER-PICK-LIMIT`, `SERVER-PICK-CARRYING`, `SERVER-PICK-OFF`.
- **Page:** Channels → "Servers of the channels": the current server of each channel, its servers with ping, the best one marked, the last change, and the switch "Pick the best server". The panel is a separate module loaded only when opened; the first screen got smaller.

Not yet verified on the router: the WAN path of the measurements, the server change of an idle channel while the other one carries traffic, and the rule rebuild after it.

**Что изменилось по сравнению с 2.0.0-beta5:** подбор лучшего сервера внутри канала (решение владельца 02.11.2026). **По умолчанию выключен** до проверки на роутере:
- роутер меряет серверы из списка GL каждого канала через провайдера, не чаще раза в 10 минут и сразу после сбоя канала: OpenVPN — по времени TCP-соединения, WireGuard — пингом;
- лучший рабочий сервер ставится в списке сразу за текущим, и собственный перебор серверов прошивки берёт его следующим;
- упавшему каналу, который не везёт трафик, программа ставит лучший сервер тем же способом, что и GL (uci и ifdown/ifup только этого интерфейса); Auto должен быть включён;
- ограничения: канал с трафиком не трогается никогда; рабочий сервер меняется только на сервер быстрее хотя бы на 20 %; не больше 4 смен в час на канал; идущую смену сервера самой GL программа не прерывает;
- новые коды: `SERVER-PICKED`, `SERVER-PICK-FAILED`, `SERVER-PICK-WAITING-VENDOR`, `SERVER-PICK-LIMIT`, `SERVER-PICK-CARRYING`, `SERVER-PICK-OFF`;
- страница «Каналы» → «Серверы каналов»: текущий сервер каждого канала, его серверы с пингом, лучший отмечен, последняя смена и выключатель «Подбирать лучший сервер». Панель — отдельный модуль, загружается только при открытии; первый экран стал меньше.

Ещё не проверено на роутере: путь замеров через провайдера, смена сервера у простаивающего канала, пока трафик идёт по другому, и перестройка правил после неё.
