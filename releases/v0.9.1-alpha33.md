# Auto VPN 0.9.1-alpha33

Speed tests now pause the Auto controller and background monitoring after both processes acknowledge a safe loop boundary. Existing VPN connections, routes and enablement are retained. Monitoring takes a fresh observation before Auto continues. Completion, failure, cancellation and lost-worker recovery release the bounded pause; a manual Stop is never overwritten. CPU admission uses current CPU accounting after the pause. A normal measurement time boundary preserves fully completed payload samples instead of reporting a false cancellation.

The diagnostic reference table fits the viewport, including expanded explanations and long codes; mobile fields stack vertically. VPN-003/DNS text distinguishes partial success, no validated response and unknown detail. The journal correlates duplicate rows only with saved same-measurement evidence, shows temporary vendor contention as waiting, and distinguishes pending Start from an earlier stopped observation. Examples no longer promise a failed-primary cause, external-LAN confirmation or successful Stop recovery without evidence. Bounded per-endpoint HTTP/TLS/timeout results reach the authenticated UI through the identity guard and are removed on a rebind.

Validation: immutable Python 3.11/3.9 Linux matrices each passed 839 application and 113 QA tests, with complementary platform skips; 64 UI suites; native Chromium/CDP 4×46 checks. Dedicated MT3000/GL.iNet 4.11.0: normal installation, 92 file/mode checks, actual HTTP/RPC, ordinary Auto startup and both bounded speed tests passed. During the test the two daemons performed no new checks/decisions and averaged 0.94% total CPU; intent, configuration and service PIDs were preserved. Auto returned to RUNNING / OBSERVING. Encrypted pre/post exports were independently decrypted and read.

Quad9 HTTP/1.1 incompatibility remains explicitly reported as a check-endpoint HTTP505 response; the two-success HTTPS quorum is unchanged. Router probes and these speed samples are not external-LAN, injected-failover, reboot or long-endurance acceptance. На время теста скорости Auto и фоновый мониторинг приостанавливаются после подтверждения безопасной точки обоими процессами. VPN остаются подключёнными. После теста сначала возвращается мониторинг, затем Auto; ошибка и отмена тоже снимают паузу. Ручной Stop не отменяется. CPU проверяется после паузы; окончание заданного времени замера сохраняет успешно полученные данные.

Таблица справочника помещается по ширине, включая длинные коды и раскрытые пояснения. Диагностика различает частичную доступность, отсутствие подтверждённых ответов и неизвестные сведения. Один замер не дублируется как два сбоя; занятость GL.iNet показывается как ожидание, прежний STOPPED после Start — как ожидающий подтверждения запуск. Исправлены недостоверные справочные примеры. Отдельно показываются HTTP/TLS/тайм-ауты проверочных адресов; их ошибка не объявляется полным отсутствием VPN-трафика.

На физическом MT3000 проверены установка и оба теста скорости с паузой и автоматическим восстановлением. VPN, конфигурация и процессы служб сохранены. Auto оставлен включённым. После установки обновите страницу Ctrl+F5.
