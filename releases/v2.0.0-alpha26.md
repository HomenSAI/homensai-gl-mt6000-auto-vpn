# HomenS.AI Auto VPN 2.0.0-alpha26 (Lua line, test build)

**Runtime:** as 2.0.0-alpha25.

- **Faster return after a power cut** (Python and Lua alike; analysis in `docs/architecture/BOOT-RECOVERY-2026-11-01.ru.md`):
  - the boot rollback retries every 5 s instead of 20 s;
  - the boot resume tries Start every 5 s instead of 15 s;
  - a Stop pressed during the boot window wins at once;
  - if the pair start that the resume Start queued fails, Start is pressed again, at most twice within 240 s. In the 3 h soaks, Auto stayed off after every idle power cut until the bench pressed Start.
  - Each recovery step in the first 600 s of uptime is logged as `BOOT-RECOVERY-STEP`.
- **The 45 s vendor settle cap now applies everywhere.** alpha24 capped it in the shared helper, but the Auto diagnostic, the fault check and the candidate ranking still computed 2 × the probe interval themselves (120 s at level 1). The alpha24 soak still showed ~125 s blocks after a killed Auto.

2.0.0-alpha26 — отдельная линия Lua, тестовая сборка.

Быстрее возврат после отключения питания. Auto сам повторяет запуск, если первый не удался: в 3-часовых тестах после отключения в покое Auto оставался выключенным, пока его не включали вручную. Ожидание прошивки не больше 45 с теперь действует везде: в alpha24 главная проверка Auto всё ещё ждала 120 с.

**Ядро:** Python 3.9 — основа и запасной уровень; Lua 5.1 — монитор и Auto (две службы, по умолчанию); C — модуль JSON внутри Lua.

CI source `518f702728e4dfd9018be3f56fde2d5921e803a0`: pinned Python 3.11 and 3.9, all suites pass. The isolated Python 3.9 build is identical.
