# Auto VPN 0.9.1-alpha61

Alpha61 contains the alpha60 fixes for the cause of failed manual and automatic switches on the dedicated GL-MT3000. A real switch spends about 46–52 s in APPLYING there, about 35 s of it before the vendor rule rebuild (rtp2) starts, while the parent waited at most 50 s. Roughly half of the attempts were therefore killed in the middle of the vendor rebuild. This left a flushed mangle graph, a stale rtp2 lock and a partly regenerated firewall (a missing vendor `gl_vpn_rules` forwarding), with the pair held for recovery.

- Switch budget: 120 s transaction. The vendor rebuild starts only if at least 75 s remain; otherwise the switch is refused before any kernel change and rolled back cleanly. The parent waits deadline + 5 s; rtp2 is stopped with SIGTERM first so its own trap removes the lock. One redundant diagnostic before the reorder was removed.
- Recovery: a narrow product path recovers exactly an interrupted vendor rebuild (dead worker, stale lock of a dead process, graph that routes nothing, only vendor firewall sections differing). Every write is re-checked; success requires the original order, kernel attestation of the original channel and all protected configuration digests equal to the originals. Anything else keeps the existing refusal. Auto stays OFF; no automatic Start; budget unchanged.
- Interface: one transition/recovery model and one timer for all zones; "recovery needed" instead of suggesting the owner changed settings; fixed primary/reserve order; the owner's channel texts; 2-minute limit.
- Upgrade path: the lifecycle guard now allows an upgrade over an interrupted journal only when no apply child is alive anywhere, Auto is off and native status is STOPPED/BLOCKED; the journal, guard and pair state stay untouched for the new supervisor. Removal keeps refusing. prerm passes "upgrade" only for opkg upgrades. Note: the installed alpha57 prerm still refuses such an upgrade; see the completion report.
- Evidence: four crash/recovery replays with a real separate process, SIGKILL and an OpenWrt QEMU guest kernel (PASS on alpha60, FAIL on alpha57). The real GL rtp2, procd and the physical router are separate gates in the [completion report](../docs/handoff/SWITCHING-FINISH-2026-10-29.ru.md).

CI source `6451ea53c8220455f97e0780d34de611a48fd599`: pinned Python 3.11.2 and 3.9.15, 1241/1241 application tests without skips each, 150 QA tests (2/37 explicit skips), 60 lab, 13 Lua, 20 tools; 83 UI suites in 3.11. The isolated build is identical.

Alpha61 (включает alpha60) устраняет причину неудачных ручных и автоматических переключений на MT3000: реальное переключение длится 46–52 с, из них около 35 с до запуска штатного rtp2, а родитель ждал не больше 50 с и прерывал штатную перестройку правил посередине. Теперь бюджет 120 с, перестройка запускается только при достаточном запасе времени, rtp2 останавливается корректно, а прерванная штатная перестройка восстанавливается узким проверяемым путём без запуска Auto. Интерфейс показывает одну операцию, один таймер и «нужно восстановление» без обвинения владельца. Также разрешено обновление поверх прерванного журнала при мёртвом рабочем процессе.
