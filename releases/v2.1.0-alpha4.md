# HomenS.AI Auto VPN 2.1.0-alpha4 (Lua line, server pick stage 3 fix)

**Runtime:** as 2.1.0-alpha3 (Lua by default, Python as the fallback; the same logic and shared test cases).

**Changes since 2.1.0-alpha3:**
- **The failed primary now really gets its new server.** The server check that a failure starts often runs a few seconds before Auto has moved the traffic to the reserve. It then saw the failed channel still carrying the traffic, skipped it (`SERVER-PICK-CARRYING`) and never came back to it. Found on the MT3000 router on 02.11.2026: the OpenVPN primary's server was cut off, Auto went to the reserve after 26 s, and the server was not changed. Now both monitors run the check for that channel once more 20 s later, when the reserve carries the traffic. Only one extra check per failure: a channel that keeps carrying the traffic (for example the reserve is down too) is not checked again before the usual 10 minutes.
- Router finding about WireGuard (no code change): the NordVPN WireGuard profiles on the test router connect through a pool address (`berlin.de.wg.nordhold.net`). When one address of the pool is cut off, the tunnel reconnects to another address by itself and the primary comes back on the same profile in about 2 minutes. A server change is not needed there, and the check correctly changes nothing when all servers are alive.

**Что изменилось по сравнению с 2.1.0-alpha3:**
- **Упавший основной канал теперь действительно получает новый сервер.** Проверка серверов, которую запускает сбой, часто шла за несколько секунд до того, как Auto перевёл трафик на резерв. Она видела, что упавший канал ещё несёт трафик, пропускала его (`SERVER-PICK-CARRYING`) и больше к нему не возвращалась. Найдено на роутере MT3000 02.11.2026: сервер основного OpenVPN отрезан, Auto через 26 с ушёл на резерв, а сервер так и не сменился. Теперь оба монитора повторяют проверку этого канала через 20 с, когда трафик уже идёт через резерв. Повтор только один на сбой: канал, который так и несёт трафик (например, резерв тоже не работает), снова проверяется не раньше обычных 10 минут.
- Наблюдение на роутере про WireGuard (код не менялся): профили NordVPN WireGuard на тестовом роутере подключаются через общий адрес пула (`berlin.de.wg.nordhold.net`). Если один адрес пула отрезан, туннель сам подключается к другому, и основной канал возвращается на том же профиле примерно за 2 минуты. Смена сервера там не нужна, и проверка правильно ничего не меняет, когда все серверы живы.

Still **off by default** ("Pick the best server" on the Channels page). / По-прежнему **выключено по умолчанию** («Подбирать лучший сервер» на странице «Каналы»).
