# HomenS.AI Auto VPN 2.0.0-alpha11 (Lua line, test build)

**Runtime:** this is the separate Lua line (branch `feat/lua-core-20261030`); the Python line 1.0.0-betaN stays the fallback. By default everything still runs on Python 3.9, exactly as 1.0.0-beta13. Switches that move parts to Lua 5.1 (each can be used alone; `lua_core` from 1.0.0-beta13 still exists):

| Part | Default | `option lua_auto '1'` | `option lua_monitor '1'` |
|---|---|---|---|
| Auto supervisor (pair loop, transaction, rollback and recovery, manual pair button, history writes) | Python | **Lua** (`lua/auto.lua daemon`) | — |
| Monitor (probes of both channels, vendor epochs, probe levels, accounting, `status.json`) | Python | — | **Lua** (`lua/monitor.lua daemon`) |
| Page reads (`status`, `events`, `history`, `auto_live`, `inventory`) and `setup_probe/response/stats` | Python | — | **Lua** (ubus `homensai-vpn-lua` behind the rpcd dispatcher) |
| Kernel route proof and manual-button state for the page | Python | — | Python, through the bridge `status_bridge.py` (only while the page is open) |
| Live probe of a profile before a switch/return | Python | Python, through `lua_bridge.py` | — |
| Manual channel button (`pair_manual`, instant path) | Python | Python | **Lua** (`manual_request.lua`; `resume`, a busy lock or a speed pause → Python) |
| Buttons `native_start/stop`, `fault_*`, speed test, Telegram | Python | Python | Python |

- **Manual hold re-check:** after a manual switch the Lua supervisor re-proved the held channel with a live probe on every pass, and each probe starts Python through the bridge (~30 % of a core measured on the MT3000 while a hold lasted). The steady hold now reuses a positive live probe for up to 30 s; transitions always probe live.
- **Measured with alpha10, both services in Lua:** manual click request answered in 0.04 s (1.2 s through `agent.py`), traffic on the new channel after 2.65 s, done after 5.0 s; monitor 2.4 % CPU, 9.5 MB.
- **Manual button request in Lua (plan item 4, first step).** With both services in Lua the click started `agent.py` (request 1.2 s, done 6.0 s measured on the MT3000 with alpha9). The Lua monitor now answers `pair_manual` itself: the same field checks, light gate and codes as Python, then the QUEUED row under a non-blocking control lock (Python's `pair_manual.valid()` accepts it). The supervisor still diagnoses and proves every switch.
- **Measured with alpha9, both services in Lua (same conditions as Python: level 1, a probe every 60 s):** monitor 3.4 % CPU and 8 MB (Python 4.6 % and ~37 MB), page `status` 0.09 s (0.14 s).
- **Lua monitor CPU and probe errors (profiled on the MT3000 with alpha8):** ~80 % of the monitor's CPU was the Python-style shortest float text, recomputed for thousands of unchanged numbers every pass; each number's text is now kept (bounded cache, identical output). Probe `COMMAND-FAILED` with `sh: write error: Broken pipe`: the SIGCHLD of the monitor's own curl children interrupted the pipe read; short commands now write to a RAM file instead of a pipe. With alpha8 no probe pass hit the 60 s watchdog any more.
- **Lua monitor, first run on the MT3000 (alpha7, step C):** both services on Lua used 12.1 MB (monitor) and 10.6 MB (Auto), against ~77 MB for the two Python services; the page answered in 0.43 s. But the monitor took ~25 % of a core and twice in 5 minutes a probe pass did not finish in 60 s, so the monitor was returned to Python (Auto stayed on Lua). alpha8: every armed `uloop` timer, fd watch, child and socket is held until it completes (libubox-lua objects cancel themselves when garbage-collected, which a long-running daemon hits and a one-shot run does not); the watchdog logs what was pending; an on-request profiler for the monitor (`lua-monitor-profile.request`).
- **Lua monitor merged (plan items 2–3).** `option lua_monitor '1'` runs the monitor in Lua: device-bound probes without SO_MARK (nixio `bindtodevice`, raw ICMP, `curl --interface` for HTTPS), vendor epochs, probe levels and boost, accounting, the same `status.json`; the page's reads and the probe/response/statistics settings are answered by Lua through the rpcd dispatcher; removing `/var/run/homensai-vpn/lua-monitor.ready` returns the page to Python at once. Its read-only comparison on the MT3000 matched Python (6.1 MB). Off by default.
- The Lua modules report the package version (`lua/version.lua`).
- **status.json: only the fields the supervisor reads.** `canon.decode_keys` builds `time`, `error`, `profiles`, `samples`, `vendor_observation`, `uplink_observation`, `observation_valid_for` (the same keys the Python supervisor reads) and skips the statistics structurally. On the live MT3000 file (230 KB): identical values, 360 → 170 ms per parse; with the single parse per version, ~720 → 170 ms per monitor write.
- **Less CPU at idle:** the monitor's `status.json` (205 KB, rewritten every 10.5 s) is decoded once per version for every reader of the supervisor (it was decoded twice; the exact pure-Lua decoder takes 380 ms per parse on the MT3000).
- **Diagnostics profiler:** `touch /var/run/homensai-vpn/lua-profile.request` profiles the Lua supervisor for 60 s into `lua-profile.json` (RAM); off by default.
- **Measured with alpha4:** `kill -9` of the Lua supervisor during APPLYING — restarted after 5 s, journal rolled back 9.5 s after the kill, pair cleanup finished, LAN guard removed (Auto off afterwards by design, as in Python).
- **Measured on the MT3000 with alpha3** (Lua Auto, the same router and channels as the Python baseline 1.0.0-beta13): idle Auto 22.5 % of one core and 12.1 MB (Python 55.7 % and 40.6 MB); 6 of 6 instant manual switches, traffic on the new channel after 2.6 s (1.9–3.6) and the button done after 4.0 s (Python 4.1 s / 5.5 s); 2 of 2 controlled faults switched to the reserve (COMMITTED 65–97 s after the fault) and returned to the primary (211–216 s).
- **Fix after the third router run (alpha3):** a kill during APPLYING was recovered correctly (journal rolled back in 7.4 s, Auto switched off by design as in Python), but the pair cleanup then failed with `PAIR-NETWORK-WRITE-FAILED`: the in-process copy of the packaged network write did not get its job on stdin. It now reads its own stdin; the router self-test runs the real network read and write in-process on a copy of the network config.
- **Fixes after the second router run (alpha2):** the Lua supervisor reached OBSERVING like Python, then crash-looped: nixio takes file modes only as strings, `nixio.open` does not take `'wx'`, and the MT3000 has no `stat(1)`. Modes are now octal strings, exclusive create uses `nixio.open_flags`, and the exact mode check reads nixio's `modestr` cross-checked with `modedec`.
- **Router self-test of the system layer** (`router_sys_selftest.lua`): every `sys` call against the router's own nixio/libubus/libuci from a `/tmp` copy, run before Lua is enabled.
- **Safety net `LUA-AUTO-FALLBACK`:** after 3 Lua errors within 10 minutes the process releases its lock and replaces itself with the Python supervisor (system log, error table, `RUNTIME/lua-auto-fallback.json`).
- **Fix after the first router run of alpha1:** with `lua_auto=1` the Lua supervisor stopped with `sys: unsafe command argument` when it armed the LAN guard release at Auto start (the release job holds the quoted nft element `'{ "br-lan" }'`, which the command quoting refused). procd restarted it and it recovered to STOPPED, so Auto did not start; nothing was switched and no guard was left. The job is now handed to `sh -c` with its own quotes escaped; a new test drives the real `sys.lua`.
- **Lua Auto supervisor (Lua plan item 1).** `backend.lua` ports `native_switch.Linux`, `recovery.lua` ports the rollback recovery, `auto.lua` runs under procd when `lua_auto` is on. The same files, journal phases, control revision, lock and refusal codes as Python; both supervisors take `native.lock`, so they never run together. Every input is cached by a cheap key (file inode/size/time, command text), so an idle pass costs milliseconds instead of re-running the helpers.
- **Known gaps with `lua_auto=1`** (listed in `docs/architecture/LUA-AUTO-ITEM1-2026-10-31.ru.md`): the speed test refuses `SPEED-PAUSE-UNVERIFIED`; the old non-pair manual queue is not served; switch events in the history have no latency/website captures.
- **Router check before this build** (MT3000, read-only, Python Auto running): the Lua backend reads the same uci, kernel rules, plan, kernel proof and journal and gives the same answers as Python; diagnostic with cache 115 ms against 750–850 ms in Python, 7.1 MB.
- Measurements of the supervisor on the router (idle CPU, memory, recovery after kill, Stop during a switch, automatic faults) are recorded in `docs/architecture/LUA-PLAN-2026-10-30.ru.md`, row 1.

alpha11: удержание после ручного переключения перепроверяет канал живой проверкой не чаще раза в 30 с (было каждый проход через запуск Python — ~30 % ядра). Замеры alpha9 (обе службы на Lua, условия как у Python): монитор 3,4 % процессора и 8 МБ (Python 4,6 % и ~37 МБ), ответ страницы 0,09 с. alpha9: профиль монитора на роутере — ~80 % процессора уходило на форматирование дробных чисел как в Python; текст каждого числа теперь запоминается. Ошибки проверок «Broken pipe» — чтение вывода команд прерывалось сигналом от дочерних curl; теперь вывод идёт через файл в ОЗУ. alpha8: первый запуск монитора на Lua (alpha7) — память 12 МБ вместо ~40, но ~25 % процессора и два «проход не завершился за 60 с»; монитор возвращён на Python, Auto остался на Lua. Исправлено удержание объектов uloop от сборщика мусора, добавлены диагностика сторожа и профилировщик монитора. alpha7: в линию влит монитор на Lua (`option lua_monitor '1'`, по умолчанию выключен): пробы каналов, эпохи туннелей, уровни проверок, учёт и чтение страницы — на Lua; кнопки, тест скорости и Telegram — на Python. alpha6: из status.json разбираются только 7 полей, которые читает супервизор (360 → 170 мс на разбор). alpha5: одно чтение status.json монитора на версию файла (было два, по 380 мс); профилировщик по запросу. С alpha4: kill супервизора во время переключения — откат за 9,5 с, уборка завершена.

Замеры alpha3 на MT3000: Auto в покое 22,5 % ядра и 12,1 МБ (Python 55,7 % и 40,6 МБ); ручное переключение — трафик 2,6 с, кнопка 4,0 с (Python 4,1/5,5 с); 2 из 2 автосбоев с возвратом. Исправлено после третьего запуска (alpha3): уборка пары после kill не могла записать сеть (встроенный скрипт не получал stdin).
