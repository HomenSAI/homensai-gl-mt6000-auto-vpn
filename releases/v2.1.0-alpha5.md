# HomenS.AI Auto VPN 2.1.0-alpha5 (Lua line, server pick stage 3 fixes)

**Runtime:** as 2.1.0-alpha4 (Lua by default, Python as the fallback; the same logic and shared test cases).

**Changes since 2.1.0-alpha4:**
- **The failed primary's server change is no longer refused.** On the MT3000 router on 02.11.2026 the alpha4 retry worked: the check found the live OpenVPN server and handed over the change (40354_2020 -> 40354_2016). But Auto refused its own correct change and also its rollback (`SERVER-PICK-FAILED`, "rollback failed"). It expected the two pair rules in a fixed arrangement, while the real session had started with the reserve rule first. Now the reserve rule, which keeps its id, tells Auto where the pair stands. A regression case made from the captured router data is shared by both runtimes; the old code refuses it.
- **Power cut in the middle of a server change:** after the reboot Auto keeps the new server only if it had already passed its check. Otherwise it puts the previous server back. It never touches the tunnel that carries the traffic.
- **A rollback that stopped half way** (an error after the settings were written) is finished on the next step of Auto. Before, Auto then took its own change for an outside change.
- **After a reboot** Auto always reads the switch record again after finishing a server change, so it never compares an old copy.
- New tests: the extra server check after a failure runs exactly once per failure, in both monitors.

**Что изменилось по сравнению с 2.1.0-alpha4:**
- **Смена сервера упавшего основного канала больше не отклоняется.** На роутере MT3000 02.11.2026 повтор проверки из alpha4 сработал: проверка нашла живой сервер OpenVPN и передала смену (40354_2020 -> 40354_2016). Но Auto отклонил свою же правильную смену и откат к прежнему серверу (`SERVER-PICK-FAILED`, «rollback failed»). Он ждал правила пары в одном определённом порядке, а настоящий сеанс начался с правилом резерва впереди. Теперь Auto определяет положение пары по правилу резерва — его имя при смене не меняется. Случай из записанных на роутере данных добавлен в общие тесты обоих вариантов; старый код его отклоняет.
- **Сбой питания посреди смены сервера:** после перезагрузки Auto оставляет новый сервер, только если тот уже прошёл проверку. Иначе возвращает прежний. Туннель, который несёт трафик, не трогается никогда.
- **Откат, прерванный на середине** (ошибка после записи настроек), доводится до конца на следующем шаге Auto. Раньше Auto принимал свою же правку за чужую.
- **После перезагрузки** Auto всегда заново читает запись переключения после смены сервера и не сравнивает устаревшую копию.
- Новые тесты: дополнительная проверка серверов после сбоя идёт ровно один раз на сбой, в обоих мониторах.

Still **off by default** ("Pick the best server" on the Channels page). / По-прежнему **выключено по умолчанию** («Подбирать лучший сервер» на странице «Каналы»).
