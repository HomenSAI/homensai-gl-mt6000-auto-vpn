# v0.9.0-alpha27 — MT3000 native trials and model selection

Adds Automatic / GL-MT6000 / GL-MT3000 choice in first-run setup and Settings, actual hardware identity, persistence and final-writer mismatch rejection. Device preference never bypasses platform checks.

The MT3000 adapter is restricted to the verified 4.11.0 / MT7981 / 5.4.211 / aarch64 FW3 arrangement and WG1/OV1 pair, exact vendor sources, disabled accelerators and bounded existing-rule transitions. The controller now models the exact derived GL.iNet process rule in its journal, waits for asynchronous firewall/DNS work and starts explicit private calibration without erasing Stop. Hosted IPv4 proof stays separate from external-LAN certificates in confirmation, history, UI and fault eligibility. The Windows helper never writes routes, including CheckOnly.

Validation: 655 application and107 QA tests in Python3.9/Lua and3.11,33 Node UI suites,40 focused lab checks, reproducible Linux IPK. Actual MT3000 native calibration, bounded source fault, Auto reserve and automatic return, Stop, manual reserve/return passed with ordinary hosted DNS/2HTTPS. Alpha27 also passed supervisor SIGKILL recovery in WAIT-CLIENT: original route/data restored, lease and quota preserved, no false certificate. Monitor off/on and reboot persistence were checked.77 installed files/modes and HTTPS assets match the IPK.

A reboot exposed stock VPN/SFE startup interference; the dedicated test router now uses documented, reversible boot prerequisites. See docs/MT3000-OPERATIONS-2026-10-22.md. Auto is stopped after tests. These are router-hosted IPv4 results: the external Windows LAN path remains unverified because host route/NIC changes were refused. No external-LAN certificate, MT6000 hardware requalification, six-hour traffic soak or physical power-cut proof is claimed. The release remains experimental and bounded.
