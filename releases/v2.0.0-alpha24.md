# HomenS.AI Auto VPN 2.0.0-alpha24 (Lua line, test build)

**Runtime:** the fastest measured configuration is now the installed default (owner decision 01.11.2026). The Lua monitor and the Lua Auto supervisor run as two services (`lua_monitor` and `lua_auto` are on unless set to '0'), with the C JSON module. Python 3.9 stays the fallback: after `LUA-AUTO-FALLBACK`, without a Lua interpreter, or with the options set to '0'.

Faster automatic failover (owner decisions 01.11.2026, measured on the MT3000; the same rules in the Python and Lua cores):

- **Fast detection is on by default.** The 1 s heartbeat of both Auto channels starts a dense confirmation within about 3 s of an outage. `option lua_fast_detect '0'` turns it off. Measured with it on, at probe level 1: the Auto decision came 26–28 s after the fault, instead of 58–88 s.
- **Shorter HTTPS wait during a dense confirmation:** 3 s instead of 6 s, and only for the monitor's checks of a channel that is already suspected. The failure count (3), the DNS check and Auto's own confirmation probe are unchanged.
- **Vendor settle period of at most 45 s** (variant B). It no longer depends on the probe level: it was 120 s at level 1. Two equal observations and the firmware-worker quiet check (`VENDOR-WORKER-BUSY`) are still required.
