# HomenS.AI Auto VPN 2.0.0-alpha14 (Lua line, test build)

**Runtime:** the separate Lua line. New in this build: `option lua_core_process '1'` (with `lua_monitor='1'` and `lua_auto='1'`) runs the monitor and the Auto supervisor in ONE Lua process `hv_core.lua` (plan item 8): the supervisor's pass runs as a coroutine on the monitor's event loop and reads the monitor's status from memory; default `0` keeps the two separate Lua processes. Python 3.9 stays the base and the fallback (see the fallback chain below).

| Part | Default | `lua_auto=1` | `lua_monitor=1` | `lua_core_process=1` |
|---|---|---|---|---|
| Auto supervisor, live probe | Python | **Lua** | — | **Lua, in hv-core** |
| Monitor, accounting, history, page reads, buttons, channel path, speed test, Telegram | Python | — | **Lua** | **Lua, in hv-core** |
| Manual-switch panel and scan state for the page | Python | — | **Lua** (the Python bridge only after a Lua failure) | **Lua** |
| Fault test start itself, site measurement, statistics export | Python | Python | Python | Python |

Fallbacks: hv-core 3 crashes in 600 s → two Lua processes (`HV-CORE-FALLBACK`); hv-core loop stall > 120 s → restart (`HV-CORE-WATCHDOG`); Lua Auto 3 errors in 10 min → Python supervisor (`LUA-AUTO-FALLBACK`); Lua monitor missing → `agent.py` answers the page.

- **Power cut during a manual hold (soak test on alpha13):** after the reboot the held journal could not be closed because the pair's own tunnels stayed down (the pair starts them itself), so Start and the automatic resume were refused `TRANSACTION-IN-PROGRESS`. Recovery now brings the pair's own clients up (same rules and budget as a normal start, Stop-fenced, LAN never blocked while waiting) and closes the journal; then the resume works. The automatic resume measured its window with the wall clock, which NTP stepped forward right after boot (no battery clock); it now uses a monotonic clock.
- **Auto resumes after a supervisor restart too (owner decision extended):** a crash/kill of the supervisor without a reboot left Auto off; Auto the owner switched on now comes back the same way as after a power cut (all Start checks; a later Stop or give-up wins; at most 3 restart resumes per 15 min).
- **Ping interval setting:** Settings → "How the response is measured": every 10 s … 5 min (default 1 min). Every table shows the last ping with its age, e.g. "42 ms (12 s ago)"; a dash only before the first ping.
- **Switch statistics:** a recovery after a fault or restart is its own episode (purple, "R"), never drawn as a switch to the reserve and never in the averages; a moment that was not saved is a dash, not 0 s.
- **No Python on page polls:** with the Lua monitor the page's manual-switch panel and scan state are computed in Lua (about −12 % of a core measured cost while the page is open on alpha13).
- **Faster JSON:** object keys are sorted natively (the byte-by-byte Lua comparator was ~1/3 of the supervisor's CPU during manual switches).

2.0.0-alpha14 — отдельная линия Lua, тестовая сборка.

Новое: один Lua-процесс `hv-core` (монитор + Auto, флаг `lua_core_process`); тупик после отключения питания во время ручного удержания исправлен (восстановление само поднимает туннели пары); автоматическое включение Auto отсчитывает время по монотонным часам (после загрузки часы прыгали по NTP) и срабатывает также после аварийного перезапуска службы (решение владельца); настройка частоты пинга (10 с – 5 мин, по умолчанию 1 мин) и «последний пинг (N с назад)» во всех таблицах; восстановления в статистике переключений — отдельный вид эпизода; страница больше не запускает Python; ускорена сборка JSON.

**Ядро:** Python 3.9 — основа и запасной уровень; Lua 5.1 — монитор, Auto, страница, кнопки, тест скорости, Telegram (две службы или один процесс hv-core). На Python остаются запуск самого теста сбоя, замер сайтов и выгрузка статистики.
