# HomenS.AI Auto VPN 2.0.0-beta4 (Lua line, stable candidate)

**Runtime:** as 2.0.0-beta3.

Fixes from the MT3000 checks of beta3 (01.11.2026):
- **Program file integrity on the GL firmware.**
  - The checker read file permissions with `stat`, which the GL busybox does not have. Every file looked like a permission mismatch, so the pristine copy was refused.
  - After an instant reboot the service then stayed off: the gate chose "stopped" with nothing to restore from. The VPN-only guard stayed in place.
  - Permissions are now read from `ls -ln`. On the router the check took 0.21 s and passed.
  - A permission-only difference is now `INTEGRITY-MODE-DIFFERS` and never stops a layer. Only real content damage can.
- **Start on the reserve after a power cut (`BOOT-RESERVE-ADOPTED`).**
  - On beta3 the handover never happened.
  - It now retries for up to 60 s while the tunnels come up after boot.
  - It needs only the reserve up and healthy, checked by a live probe; the primary may still be connecting.
  - Each refusal reason is logged once as `BOOT-RECOVERY-STEP: handover refused <reason>`.

Measured on beta3, LAN client test with the primary cut for 90 s: the outage until the reserve carried traffic was 22.8 s (beta1: 40.3 s). DNS failed only until the switch, 19.9 s (beta1: the whole 90 s). Leaks: 0.
