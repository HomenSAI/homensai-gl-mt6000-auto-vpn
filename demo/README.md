# Локальная демонстрация HomenSAI Auto VPN

После массовых испытаний исправлены WAN-разрешение, свежесть рейтинга, таймеры восстановления, цепочки повторных попыток и независимость месячных/переходных счётчиков от коротких логов. Результаты: [1200 генерируемых сценариев, 4096 сочетаний флагов и длительный прогон](../qa/STRESS_REPORT.md).

Интерфейс: http://127.0.0.1:8798/ . Контейнер: alta-vpn-demo. Измерения, история и переключения полностью искусственные. Демонстрация не подключается к роутеру и не читает VPN-ключи.

## Что можно попробовать

1. Переименовать канал кнопкой карандаша, добавить канал и сервер, выбрать OpenVPN/WireGuard. Стрелки меняют приоритет каналов и серверов. ID сохраняется при переименовании.
2. Нажать «Отказ текущего сервера», затем трижды «+5 секунд»: модель выберет следующий сервер внутри канала.
3. Сбросить демонстрацию и выбрать «Отказ текущего канала», затем три шага: модель перейдёт на резервный канал и другой протокол.
4. Проверить DNS, WAN, отказ всех VPN, неизвестный путь и неудачное применение с откатом. «Следующее переключение неудачно» вооружает ошибку следующего перехода; затем задайте отказ сервера/канала.
5. Запустить ускоренное моделирование: 1 реальная секунда = 5 модельных секунд. Пауза останавливает время. «Восстановить всё» снимает отказы; автоматический возврат выдерживает установленные интервалы.
6. Смотреть графики и статистику за час/сутки/неделю, фильтровать события по именам, кодам и протоколам, раскрывать подробности и экспортировать JSON.

Названия, приоритеты и настройки сохраняются в localStorage этого браузера. История хранится только в памяти страницы и при обновлении заменяется искусственной недельной историей. «Сбросить демонстрацию» сохраняет пользовательскую конфигурацию, но сбрасывает модельное состояние. Архивирование скрывает объект из очереди, сохраняя его ID для истории. Активный объект сначала нужно заменить другим. В первой версии максимум 20 каналов и 20 серверов на канал, включая архивные записи.

## Запуск и управление

Используется уже установленный Docker-образ local-dev-tools:installed. Из корня репозитория:

```sh
docker compose -f demo/compose.yaml up -d
docker compose -f demo/compose.yaml down
```

Текущий экземпляр был запущен через docker run с теми же ограничениями. Для его остановки и повторного запуска:

```sh
docker stop alta-vpn-demo
docker start alta-vpn-demo
```

Не запускать compose поверх одноимённого контейнера, созданного docker run: сначала остановить и удалить только контейнер alta-vpn-demo (исходники находятся на хосте). Другие контейнеры не затрагивать.

Статический Python-сервер публикуется только на loopback хоста, файловая система контейнера и mount исходников только для чтения. Нет API изменения маршрутов. Отсутствующие пути возвращают 404. Для запуска без Docker: python demo/server.py; по умолчанию сервер слушает 127.0.0.1:8798.

## Проверки и границы

```sh
node demo/test_model.js
python -m unittest discover -s prototype -v
```

JavaScript-модель расширяет первый Python-прототип очередями серверов и каналов; эти реализации не являются одним общим кодовым ядром. Для роутерного адаптера потребуется выбрать единое ядро и проверить соответствие поведения. WAN fallback здесь существует только как состояние модели. Специальные банковские правила, IPv6, реальный conntrack, procd/UCI и LuCI-интеграция не выполняются.

Задержки и объёмы искусственные. Доступность считается по известным интервалам, неизвестные показаны отдельно. Общий счётчик переходов уникальный; счётчик смены протокола может пересекаться со счётчиком смены канала. Эффективность учитывает и неудачные попытки. События сохраняют названия на момент события. Графики времени и объёма используют текущие пользовательские имена.

## Рейтинг, месячный трафик и монитор

«Тестировать все серверы» обновляет модельные результаты всех активных профилей. Фоновые модельные пробы происходят каждые 30 модельных секунд. Рейтинг можно группировать по каналам/протоколам, смотреть последний тест или средние за сутки/неделю. Доступность важнее скорости, затем учитываются модельные Мбит/с и HTTPS-задержка. Рекомендации выбирают только сейчас доступные подтверждённые кандидаты. Тесты WAN не портят доступность серверов, если сам WAN недоступен.

Отметьте серверы галочками и явно примените рекомендации. Опциональная отдельная галочка разрешает менять также порядок каналов. Активный выход не меняется. При новой серии результатов выбор сбрасывается, чтобы не принять невидимо обновлённую рекомендацию. По умолчанию рекомендации не применяются автоматически.

Месячная модельная история начинается первого числа в 00:00 Europe/Berlin с учётом зимнего/летнего смещения. Показываются входящий, исходящий и суммарный VPN-трафик и полнота периода. Месячный объём пока пересоздаётся из искусственной истории при reload: это не постоянный счётчик живого роутера.

Монитор служб — короткие статусы в стиле терминала: зелёный OK, красная ошибка, жёлтое неизвестное/пауза. Это только наблюдение; логика переключения отдельно. Полный модельный журнал экспортируется JSON. Заголовок и footer ведут на https://homensai.com.
